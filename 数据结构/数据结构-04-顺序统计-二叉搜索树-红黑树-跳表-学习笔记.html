1 · 顺序统计量与「同时找最大最小」 p2–p3

第 $i$ 个顺序统计量（order statistic）就是 $n$ 个元素里第 $i$ 小的那个。 三个特例：最小值是第 1 个，最大值是第 $n$ 个，中位数是第 $\lceil n/2\rceil$ 个（$n$ 为偶数时有两个中位数，讲义特意点了一句）。

单独找最小值：$n-1$ 次比较，且不能更少

$n$ 个元素里除了最大值，每个元素都「至少输过一次」—— 每次比较只能让一个元素输。 要让 $n-1$ 个元素都被确认「不是最小」，至少需要 $n-1$ 次比较。所以 $n-1$ 既是上界也是下界。

同时找最大和最小：为什么不是 $2n-2$，而是 $\lfloor 3n/2\rfloor$

朴素做法是「各扫一遍」：找最小 $n-1$ 次，找最大 $n-1$ 次，共 $2n-2$。讲义问： Can we find the minimum and maximum with less than twice the cost?

能。关键在于「一次比较能同时获得两个信息」：

  1. 把元素两两配对，每对内部比一次 → $\lfloor n/2\rfloor$ 次比较，分出「大者」和「小者」；
  2. 把每对的大者和当前 max 比，小者和当前 min 比 → 每对 2 次。

于是每 2 个元素只花 3 次比较，总共

$$\left\lfloor\frac{n}{2}\right\rfloor+\left\lfloor\frac{n}{2}\right\rfloor\times 2=\left\lfloor\frac{3n}{2}\right\rfloor\ \text{次}$$

（$n$ 为奇数时剩一个元素，最多再花 2 次。）

总比较次数 $\lfloor 3n/2\rfloor$，比 $2n-2$ 省掉约 $n/2$ 次
考试常考的「为什么更快」：朴素做法里，每个元素既要和 max 比、又要和 min 比； 成对法让「大者永远不可能成为 min、小者永远不可能成为 max」，于是每个元素只被比较一次（除了对内那一次）。
另一个必答点：$\lfloor 3n/2\rfloor$ 是最优的（下界 $\lceil 3n/2\rceil-2$），因为每个元素至少要「输一次或赢一次」才能确定身份。

2 · RandomizedSelect：借 partition 拿到 $O(n)$ p5–p10

一般的选择问题（找第 $i$ 小）如果先排序再取，是 $O(n\log n)$。讲义要证的是：能到 $O(n)$。

核心思想：partition 之后只递归一边

沿用快排的 RandomizedPartition，得到 $q$ 和 $k=q-p+1$（pivot 是区间内第 $k$ 小）：

RandomizedSelect(A, p, r, i)
    if (p == r) then return A[p];              # 只剩一个，就是它
    q = RandomizedPartition(A, p, r)
    k = q - p + 1;                            # pivot 在本区间内的名次
    if (i == k) then return A[q];             # 正好是它
    if (i < k) then
        return RandomizedSelect(A, p, q-1, i);        # 只在左半找，名次不变
    else
        return RandomizedSelect(A, q+1, r, i-k);      # 只在右半找，名次减 k
「少递归一边」就是 $O(n\log n)\to O(n)$ 的全部原因

三种情况的分析（讲义 p7）

情形递归式结果依据
最坏$T(n)=T(n-1)+O(n)$$O(n^2)$等差数列求和，和排序一样慢
「最好」$T(n)=T(9n/10)+O(n)$$O(n)$主定理情形 3（$f$ 主导）
平均见下$O(n)$代换法
为什么 9 : 1 就能到 $O(n)$：主定理里 $a=1,\ b=10/9,\ f(n)=\Theta(n)$，而 $n^{\log_b a}=n^0=1$， $f(n)=\Theta(n)$ 比 $1$ 大一个多项式量级，属情形 3 → $T(n)=\Theta(f(n))=\Theta(n)$。
更直观的理由：等比级数 $n+\frac{9n}{10}+\left(\frac{9n}{10}\right)^2+\cdots=10n=O(n)$ —— 每层缩水固定比例，总和被首项压住。

平均情况：讲义那两步「What happened here?」

对上界，假设要找的元素每次都落在较大的那一半（这样只会更坏）。$n$ 种 split 等概率，于是

$$T(n)\;\le\;\frac{1}{n}\sum_{k=0}^{n-1}T\big(\max(k,\,n-k-1)\big)+\Theta(n)$$

讲义在这里打了个问号：What happened here? 答案是把「$k$ 和 $n-k-1$ 里取大者」改写成「只对 $k\ge n/2$ 求和、并把系数从 $1/n$ 变成 $2/n$」：

$$T(n)\;\le\;\frac{2}{n}\sum_{k=\lfloor n/2\rfloor}^{n-1}T(k)+\Theta(n)$$
为什么可以这样改写：当 $k$ 从 $0$ 扫到 $n-1$ 时，$\max(k,n-k-1)$ 会取到 $n-1,n-2,\dots,\lceil n/2\rceil$ 各两次（一次来自 $k$ 小，一次来自 $k$ 大）， 中间的 $\lfloor n/2\rfloor$ 只出现一次。把「每个值出现两次」提出来就是 $2/n$，再补一个 $T(\lfloor n/2\rfloor)$ 的误差（被 $\Theta(n)$ 吸收）。 所以上界成立，且只对后半段求和。

代换法：$T(n)\le cn$

归纳假设 $T(k)\le ck$（对 $k\lt n$），代入：

$$T(n)\;\le\;\frac{2}{n}\sum_{k=\lfloor n/2\rfloor}^{n-1}ck+\Theta(n) \;=\;\frac{2c}{n}\sum_{k=\lfloor n/2\rfloor}^{n-1}k+\Theta(n)$$

算那个和（$k$ 从 $n/2$ 到 $n-1$，共 $n/2$ 项）：

$$\sum_{k=\lfloor n/2\rfloor}^{n-1}k\;\le\;\frac{n(n-1)}{2}-\frac{\frac{n}{2}\left(\frac{n}{2}-1\right)}{2} =\frac{3n^2}{8}-\frac{n}{4}$$

代回：

$$T(n)\;\le\;\frac{2c}{n}\left(\frac{3n^2}{8}-\frac{n}{4}\right)+\Theta(n) \;=\;\frac{3cn}{4}-\frac{c}{2}+\Theta(n)\;\le\;cn\quad(\text{取 }c\text{ 足够大})$$
这个 $3/4$ 是本题的得分点：因为只对后一半求和，求和项只占 $\frac{3}{8}n^2$ 而不是 $\frac{1}{2}n^2$， 于是系数从 $c$ 掉到 $\frac{3}{4}c$，留出 $\frac{1}{4}cn$ 的余量去吃掉 $\Theta(n)$ 和低阶项。 如果对全部 $k$ 求和，系数恰好是 $c$，没有余量，代换法就卡住了 —— 这正是必须「只对一半求和」的原因。

3 · 最坏情况线性时间选择：五元组中位数 p11–p17

随机化选择「平均 $O(n)$、最坏 $O(n^2)$」。这一节给出一个最坏也是 $O(n)$ 的确定性算法 —— 讲义自己评价：really of theoretical interest only（常数巨大，实际不用）。但它是期末最爱考的证明。

思路：先造一个「好」的 pivot

随机化算法的不确定性来自 pivot。如果每次都能保证 pivot 落在中间一段（比如 $1/4$ 到 $3/4$ 之间）， 递归规模就按固定比例缩小，必然是 $O(n)$。所以问题变成：怎么在 $O(n)$ 时间里找到一个「大致居中」的元素？

算法五步（讲义 p12）

  1. 把 $n$ 个元素分成 $\lceil n/5\rceil$ 组，每组 5 个（最后一组可能不满）；
  2. 对每组求中位数（每组 5 个，排序只要常数次比较，所以是 $O(1)$；总共 $O(n)$）；
  3. 递归调用 Select 求出这 $\lceil n/5\rceil$ 个中位数的中位数 $x$；
  4. 以 $x$ 为 pivot 对整个数组做一次 partition，得到 $x$ 的名次 $k$；
  5. 若 $i=k$ 返回 $x$；若 $i\lt k$ 在左半递归找第 $i$ 小；否则在右半找第 $i-k$ 小。
计数论证是全节的核心：pivot 一定落在中间一半

递归式与代换法（讲义 p14 的六行）

算法要做三件事：递归求中位数的中位数（规模 $\lfloor n/5\rfloor$）、partition（$\Theta(n)$）、递归处理剩下的一侧（规模 $\le 3n/4$）：

$$T(n)\;\le\;T(\lfloor n/5\rfloor)+T(3n/4)+\Theta(n)$$

代换法，假设 $T(k)\le ck$（$k\lt n$）：

$$\begin{aligned} T(n)&\le c\lfloor n/5\rfloor+c\cdot\frac{3n}{4}+\Theta(n)\\ &\le \frac{cn}{5}+\frac{3cn}{4}+\Theta(n)\\ &=\frac{19cn}{20}+\Theta(n)\\ &=cn-\left(\frac{cn}{20}-\Theta(n)\right)\\ &\le cn\qquad(\text{只要 }c\text{ 足够大，使 }\tfrac{cn}{20}\ge\Theta(n)) \end{aligned}$$
关键数字 $19/20$：$\frac{1}{5}+\frac{3}{4}=\frac{4+15}{20}=\frac{19}{20}\lt 1$。 只要两个子问题的规模系数之和严格小于 1，代换法就能留出余量，结论是 $O(n)$。
反过来，如果系数之和 $\ge 1$（比如 $\frac{1}{3}+\frac{3}{4}=\frac{13}{12}\gt1$），这套证明就崩了 —— 这也是为什么必须用 5 个一组。
为什么不能 3 个一组（考试爱问）：若每组 3 个，中位数的中位数只能保证 $\ge n/6$ 个元素 ≤ x，于是递归式变成 $T(n)\le T(n/3)+T(2n/3)+O(n)$，而 $\frac{1}{3}+\frac{2}{3}=1$，没有余量， 代换法得不出 $cn$，实际解是 $O(n\log n)$ —— 退化成快排。7 个一组可以（$\frac{1}{7}+\frac{5}{7}\lt1$），但常数更大，所以 5 是理论最优的折中。

应用一：中位数当黑盒，选择就是 $O(n)$（p16）

如果已经有「$O(n)$ 求中位数」的黑盒，找第 $i$ 小就三步：求中位数 $x$ → 以 $x$ 为 pivot partition → 只在需要的一半递归。 每次规模减半：$T(n)=T(n/2)+O(n)=O(n)$。

应用二：最坏 $O(n\log n)$ 的快排（p17）

同样的黑盒，每次取中位数作 pivot，partition 一定对半分：

$$T(n)=2T(n/2)+O(n)=O(n\log n)$$
为什么实际不用：找中位数的常数极大（分组、递归、大量常数次比较）， 实际跑起来比随机化快排慢好几倍。它的价值是理论上证明了「最坏 $O(n\log n)$ 的快排存在」， 以及「选择问题在最坏情况下也是线性的」。

4 · 二叉搜索树 p19–p44

前面所有结构都是「静态」的（建好就查）。动态集合（dynamic set）要支持插入删除， 元素带 key 和卫星数据（satellite data），操作分两类：

查询修改
Search(S,k)、Minimum、Maximum、Successor、Predecessor Insert(S,x)、Delete(S,x)

BST 性质与中序遍历

每个节点有 key、left、right、p（父指针，根为 NULL）。 BST 性质：

$$\text{key}\big[\text{leftSubtree}(x)\big]\le \text{key}[x]\le \text{key}\big[\text{rightSubtree}(x)\big]$$
同一个 key 集合可以有多种形状；形状决定高度，高度决定所有操作的代价

中序遍历为什么有序（讲义 p23 要求证明）：对 $x$ 的子树做归纳。中序先输出左子树、再输出 $x$、再输出右子树； 由归纳假设左子树输出升序且都 $\le x$，右子树输出升序且都 $\ge x$，拼起来仍升序。

Search / Insert / 高度

TreeSearch(x, k)                      # 递归版
    if (x = NULL or k = key[x]) return x;
    if (k < key[x]) return TreeSearch(left[x], k);
    else            return TreeSearch(right[x], k);

TreeSearch(x, k)                      # 迭代版（更省栈）
    while (x != NULL and k != key[x])
        if (k < key[x]) x = left[x];
        else            x = right[x];
    return x;

Insert 就是「搜索到底，把 NULL 换成新节点」（像往链表里插）。两者都沿一条根到叶的路径走，所以：

$$T_{\text{search}}=T_{\text{insert}}=O(h)$$
$h$ 可以退化成 $n$：如果按 $1,2,3,\dots,n$ 的顺序插入，树变成一条右斜链，$h=n$， 每次操作 $O(n)$。所以讲义说「We'll keep all analysis in terms of h」—— 在没引入平衡之前，BST 的复杂度只能用 $h$ 表达，不能说 $O(\log n)$。

BSTSort：和快排是「同一件事」

BSTSort(A)
    for i = 1 to n
        TreeInsert(A[i]);
    InorderTreeWalk(root);

讲义的关键观察（p32–p35）：按 $3,1,8,2,6,7,5$ 建树，每次插入的比较过程，和快排的 partition 做的是同一批比较， 只是顺序不同（快排按层做，BST 按插入顺序做）。所以：

算法平均最坏就地额外开销
BSTSort$O(n\log n)$$O(n^2)$（有序输入）否要建树、要指针
Quicksort$O(n\log n)$$O(n^2)$是常数小

讲义问 Which is better, quicksort or BSTSort? 答案：quicksort —— 常数更小、就地、不用先建数据结构。

Successor：两种情况

（下面的「后继」= 比 $x$ 大的最小 key。）

  • $x$ 有右子树：后继 = 右子树里的最小值（一直往左走到底）；
  • $x$ 没有右子树：往上爬，直到「$x$ 是从左边爬上来的」那一刻，那个祖先就是后继。

直觉（讲义原话）：As long as you move to the left up the tree, you're visiting smaller nodes. —— 只要还在往左爬，遇到的都是更小的；一旦往右爬，就跨过了 $x$，那个父节点就是答案。

例子（上图那棵树）属于答案
successor(15)有右子树右子树最小值 = 17
successor(13)无右子树13→7（右）→6（右）→15（左，停）= 15
successor(20)无右子树一路右爬到根仍无解 → NULL

Predecessor 完全对称（把左右互换）。两者都是 $O(h)$。

Delete：三种情况

删除比插入麻烦，因为要保持 BST 性质。按孩子个数分三种：

情况做法例子（上图）
0 个孩子（叶子）直接摘掉，把父亲的对应指针置 NULL删 4、删 9
1 个孩子「拼接」（splice）：让父亲直接指向那个孩子删 13（让 7 直接指 9）
2 个孩子把 $x$ 的 key 换成后继的 key，然后去删那个后继删 6（用 7 覆盖，再删原来的 7）
为什么「2 个孩子」替换成后继就一定行（讲义 p42 专门问了这个）： 因为 $x$ 的后继是右子树里的最小值，它不可能有左孩子（否则还能更小）。 所以后继最多只有一个右孩子 —— 删它就退化成情况 0 或情况 1，不会递归下去。
这也是为什么用「后继」而不是「前驱」都一样成立，但不能随便挑一个元素来替换。

CLRS 的写法：用 TRANSPLANT 抽象「换子树」

TRANSPLANT(T, u, v)              # 用子树 v 替换子树 u
    if u.p == NIL        T.root = v
    elif u == u.p.left   u.p.left = v
    else                 u.p.right = v
    if v != NIL          v.p = u.p

TREE-DELETE(T, z)
    if z.left == NIL              TRANSPLANT(T, z, z.right)      # 情况 0/1（左空）
    elif z.right == NIL           TRANSPLANT(T, z, z.left)       # 情况 1（右空）
    else                                                          # 情况 2
        y = TREE-MINIMUM(z.right)                                 # 后继
        if y.p != z
            TRANSPLANT(T, y, y.right)                             # 先把 y 摘出来
            y.right = z.right; y.right.p = y
        TRANSPLANT(T, z, y)                                       # 再用 y 顶替 z
        y.left = z.left; y.left.p = y
细节坑（考试爱考）：当后继 $y$ 不是 $z$ 的右孩子时（即 $y$ 在右子树深处）， 必须先 TRANSPLANT(T, y, y.right) 把 $y$ 从原位摘掉，再让 $y$ 接管 $z$ 的右子树。 漏掉这一步会导致 $y$ 同时出现在两个位置。

5 · 红黑树：把高度锁在 $O(\log n)$ p45–p78

BST 的所有操作都是 $O(h)$，但 $h$ 最坏是 $n$。红黑树（red-black tree）就是在 BST 上加一层「颜色」约束， 强制高度 $h=O(\log n)$，于是所有操作自动变成 $O(\log n)$。

五条性质（p47）

#性质作用
1每个节点非红即黑定义
2每个叶子（NULL 指针）是黑的让「空」也算节点，路径长度统一
3红节点的两个孩子都是黑的不能有两个连续的红
4任一节点到其所有后代叶子的路径上黑节点个数相同保证「大致平衡」，是 $h=O(\lg n)$ 的核心
5根总是黑的简化边界（不满足时染黑即可）
性质 2 的隐含意思：把 NULL 也当成黑色叶节点之后，「每个真节点都有两个孩子」—— 这样「路径」的概念才是完整的，性质 4 才有意义。

黑高（black-height）

$\mathrm{bh}(x)$：从 $x$ 出发（不含 $x$ 自己）到任一后代叶子的路径上黑节点的个数。 性质 4 保证了它定义良好（不管走哪条路，数出来都一样）。

高度上界：$h\le 2\lg(n+1)$（讲义 p50–p53 的完整证明）

分两步，第一步是关键引理。

引理：以 $x$ 为根的子树至少有 $2^{\mathrm{bh}(x)}-1$ 个内部节点

对高度做归纳：

  • 基例：$x$ 是 NULL 叶子，高度 0，$\mathrm{bh}(x)=0$，$2^0-1=0$ 个内部节点 ✓；
  • 归纳步：$x$ 高度为正，有两个孩子。 孩子是红色时 $\mathrm{bh}$ 不变，是黑色时 $\mathrm{bh}$ 少 1，所以每个孩子的黑高 $\ge \mathrm{bh}(x)-1$。 由归纳假设，每个子树至少 $2^{\mathrm{bh}(x)-1}-1$ 个内部节点，于是 $$\big(2^{\mathrm{bh}(x)-1}-1\big)+\big(2^{\mathrm{bh}(x)-1}-1\big)+1=2^{\mathrm{bh}(x)}-1$$ 正好是 $x$ 自己那一个加上两棵子树。

第二步：把 $\mathrm{bh}$ 换成 $h$

根的黑高 $\ge h/2$ —— 因为性质 3 禁止连续红节点，所以任意路径上至少一半是黑的。于是

$$n\;\ge\;2^{\mathrm{bh}(\text{root})}-1\;\ge\;2^{h/2}-1 \;\Longrightarrow\;n+1\ge 2^{h/2} \;\Longrightarrow\;\lg(n+1)\ge \frac{h}{2} \;\Longrightarrow\;h\le 2\lg(n+1)$$
结论：$h=O(\log n)$。所以 Search、Min、Max、Successor、 Predecessor 全部 $O(\log n)$；Insert / Delete 也是 $O(\log n)$， 只是要额外修复颜色（修复本身也是 $O(\log n)$）。
注意 $2\lg(n+1)$ 里的常数 2：红黑树最坏高度约为 AVL 的两倍，换来的是插入删除只需 $O(1)$ 次旋转。

旋转：唯一改变结构的操作

插入删除时不能靠「重排 key」来修复（那会破坏 BST 性质），只能旋转。旋转保持中序不变：

$y$ 的左子树 $B$「过继」给 $x$ 当右子树 —— 这是旋转唯一要小心的地方

rightRotate(y) 到底做了什么（讲义 p68 的自问自答，四句话）：

  1. $x$ 保留它的左孩子 $A$；
  2. $y$ 保留它的右孩子 $C$；
  3. $x$ 的右孩子 $B$ 变成 $y$ 的左孩子（过继）；
  4. $x$ 和 $y$ 的父指针互换（$x$ 顶替 $y$ 的位置）。

只有常数次指针操作，所以旋转是 $O(1)$。

插入：染红 + 三种情况

基本思路（p70）：先按 BST 插入，把新节点染成红色。为什么染红？因为染红只会违反性质 3（红红相邻）， 而不会改变任何路径上的黑节点个数（性质 4 保住了）。染黑则会直接破坏性质 4，几乎无法修复。

设 $x$ 是新节点，$p$ 是父亲，$g$ 是祖父，$y$ 是叔叔（$g$ 的另一个孩子）。分三种情况：

情况条件动作之后
1 叔叔 $y$ 是红 $p$ 和 $y$ 染黑，$g$ 染红 $x\leftarrow g$，继续向上循环（violation 上移两层）
2 叔叔 $y$ 是黑，且 $x$ 是右孩子（内侧） 对 $p$ 做一次左旋 转成情况 3（$x$ 变成左孩子）
3 叔叔 $y$ 是黑，且 $x$ 是左孩子（外侧） $p$ 染黑、$g$ 染红，对 $g$ 做右旋 结束（循环退出）
为什么情况 1 可以「上移」：重染之后，$g$ 变红，而 $g$ 的父亲可能是红的 —— 于是「红红相邻」的违反 从 $x$ 那一层搬到了 $g$ 那一层。子树的黑高没有变化（$p,y$ 由红变黑各 +1，$g$ 由黑变红 −1，上下抵消）， 所以性质 4 仍然成立，可以放心继续往上修。
为什么情况 3 一次就完：旋转 + 重染之后，新的子树根是黑的，它的父亲不可能再是红（否则原来就违反了）， 所以违反彻底消除，循环退出。

例题：依次插入 10、20、30、25（讲义 p56–p66 的同类演示）

插入位置与颜色判定结果
10空树，染黑—10(B)

3020 的右孩子，染红父亲 20 红，叔叔 = NULL 黑 → 情况 3（外侧）20 染黑、10 染红、对 10 左旋 → 20(B)，左右孩子 10(R) 30(R)
2530 的左孩子，染红父亲 30 红，叔叔 10 红 → 情况 130、10 染黑，20 染红；$x$ 上移到 20（是根）→ 根染黑 → 20(B)，10(B) 30(B)，30 的左孩子 25(R)

验证最后一棵树：三条路径（20→10→NULL、20→30→25→NULL、20→30→NULL）上黑节点数都是 1（只数下面的：10 / 30 / 30），性质 4 ✓； 红节点 25 的两个孩子是 NULL（黑），性质 3 ✓。

考试最爱问的三句话： ① 新节点染红（染黑会破坏性质 4，无法局部修复）； ② 情况 2 是「内侧」情形，先旋转把 $x$ 变到外侧，否则直接重染会破坏性质 4； ③ 情况 1 处理完还要继续往上循环，情况 3 处理完直接结束。

讲义 p77 补了一句：以上是「父亲是左孩子」的三种情况；如果父亲是右孩子， 就是情况 4–6，左右完全对称（代码里把 left / right 互换即可）。

删除（p78）：讲义明确课上不 cover，只要求课后读 CLRS 14.4「了解大图景，不必抠细节」。 考试若出，通常只问「删除最多需要几次旋转」（答案：至多 3 次，而插入至多 2 次）。

6 · 跳表：用「快车线」把链表变成 $O(\log n)$ p79–p93

讲义先用一页回顾链表当动态集合用（p80）：排好序的双向链表里， Min / Max / Successor / Predecessor / Delete / Insert 全是 $O(1)$ —— 唯一慢的是 Search，因为不能随机访问，只能一个个走，$O(n)$。

目标很明确：只把 Search 降下来。

第一步：加一条「快车线」

在地铁线上加一条快车线：快车只在少数站停，坐快车走远路、到站再换慢车。链表上就是两层链表： 上层只保留一部分元素，指针跨得更远。

搜索时：先在上层往右走，走到「再走就超过目标」为止，然后下降到下层继续走。

最优的「快车站数」是多少？假设一共 $n$ 个元素，上层留 $k$ 个站。搜索代价 ≈ 「上层最多走 $k$ 步」+「下层在两个站之间最多走 $n/k$ 步」$=k+n/k$，在 $k=\sqrt n$ 时最小，代价 $2\sqrt n$。
讲义 p81 的问法就是：# of express stops should be √n (why?) and the worst case cost is 2√n。

第二步：加很多层

如果允许 $k$ 层，每层把元素分成 $n^{1/k}$ 份，则每层最多走 $n^{1/k}$ 步，总代价

$$k\cdot n^{1/k}$$

取 $k=\log n$：

$$\log n\cdot n^{1/\log n}=\log n\cdot 2=\Theta(\log n)$$
为什么 $n^{1/\log n}=2$：两边取 $\log$：$\frac{1}{\log n}\cdot\log n=1$，所以 $n^{1/\log n}=2^1=2$。 这个恒等式是跳表分析里最常被考的一步。

第三步：固定分层做不到，那就随机分层

讲义 p83 点出症结：It is hard to keep the "express stops" evenly distributed —— 插入删除会不断打破「均匀」，维护它本身就要 $O(n)$。

跳表的解法：不维护均匀性，改成抛硬币。每个元素插入时，以概率 $p=1/2$ 逐层上升： 在第 1 层；以 $1/2$ 概率进第 2 层；再以 $1/2$ 概率进第 3 层……直到抛到反面为止。

每层平均走常数步、层数 $O(\log n)$，所以搜索 $O(\log n)$

搜索代价的直觉（p85）

  1. 在顶层找位置：顶层元素个数以高概率是 $O(1)$；
  2. 确定了一个「范围」，下降一层，在这个范围内继续；
  3. 每层平均 $O(1)$ 步；层数以高概率是 $O(\log n)$；
  4. 合计 $O(\log n)$。
注意「以高概率」（with high probability, w.h.p.）这个词： 跳表是随机结构，它的 $O(\log n)$ 是概率意义上的， 不像红黑树那样对每个输入都成立。答题时写「expected / with high probability」是加分点，写成「最坏 $O(\log n)$」是错的。

层数为什么是 $O(\log n)$（p86 的 union bound）

固定一个元素 $x$，它出现在 $\ge c\log n$ 层的概率是 $(1/2)^{c\log n}=1/n^{c}$。 用联合界（union bound）对所有 $n$ 个元素取并：

$$\Pr\big[\exists x:\ x\text{ 出现在超过 }c\log n\text{ 层}\big]\;\le\;n\cdot\frac{1}{n^{c}}=\frac{1}{n^{c-1}}$$

取 $c=2$ 就是 $1/n$ —— 也就是说「层数超过 $2\log n$」的概率只有 $1/n$，这就是「以高概率」的含义。

反向分析：把搜索路径倒过来数（p87–p90）

讲义给了一个很巧的办法：不去数「搜索走了几步」，而是从目标节点倒着往回走。

  • 倒着走时，每上升一层相当于「抛硬币抛到正面」；
  • 于是访问的节点数 = 抛到 $c\log n$ 个正面所需的抛硬币次数；
  • 抛 $10c\log n$ 次得到 $c\log n$ 个正面的概率极高（Chernoff 界），所以访问节点数 $\le 10c\log n$ 以高概率成立。

讲义 p90 把它写成三个事件：$A$（层数 $\le c\log n$）、$B$（抛硬币次数 $\le 10c\log n$）、$C$（访问数 $\le 10c\log n$）。 $A\wedge B\Rightarrow C$，于是

$$\Pr[C]\;\ge\;\Pr[A\wedge B]\;\ge\;1-\Pr[\bar A]-\Pr[\bar B]\;\ge\;1-\frac{1}{n^{c-1}}-\frac{1}{n^{d}}$$

插入、删除与空间

操作做法代价

插入时「期望插入几层」正是那个几何级数：$1+p+p^2+\cdots=\frac{1}{1-p}=2$（$p=1/2$），常数。

跳表 vs 红黑树（p93 的定位）：跳表自称 a probabilistic alternative to balanced trees —— 它用随机化换掉了平衡树的复杂旋转逻辑：代码短得多、常数更小、实际更快； 代价是复杂度变成期望/高概率意义，且要多花一倍指针的空间。 Redis 的有序集合、LevelDB 的 MemTable 用的都是跳表。
