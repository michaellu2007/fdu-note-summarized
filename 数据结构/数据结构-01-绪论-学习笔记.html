1 · 三个基本概念

这门课是设计与分析的理论课，不是编程课，会涉及大量证明。

程序用某种编程语言把数据结构和算法实现出来。

2 · 数组与链表

地基假设：本课只考虑主存（Main Memory），主存允许随机访问 —— 访问任意内存单元都算「单位时间」。所有复杂度分析都建立在这个前提上。

数组的三条性质

  • 同类型元素、大小固定 —— 必须提前知道元素个数上限
  • 元素在内存中连续存放
  • 因此支持随机访问：$A[i]$ 的地址 $=$ 基址 $+\ i \times$ 元素大小，$O(1)$ 直达

代价：因为连续，插入/删除昂贵。在数组最前面插入一个元素，后面所有元素都得后移一位，$O(n)$。

链表的操作代价

操作单链表双链表
头部插入$O(1)$$O(1)$
头部删除$O(1)$$O(1)$
尾部插入$O(1)$（维护 tail 指针）$O(1)$
尾部删除不高效（无法常数时间找到前驱）$O(1)$
按值查找$O(n)$$O(n)$

双链表节点结构：[prev | key | next]，头节点的 prev 为 NIL。

核心操作伪代码

LIST-INSERT-HEAD(L, x)
1. x.next ← L.head
2. if L.head ≠ NIL
3.   then L.head.prev ← x
4. L.head ← x
5. x.prev ← NIL

LIST-DELETE(L, x)
1. if x.prev ≠ NIL
2.   then x.prev.next ← x.next
3.   else L.head ← x.next
4. if x.next ≠ NIL
5.   then x.next.prev ← x.prev

LIST-SEARCH(L, k)
1. x ← L.head
2. while x ≠ NIL and x.key ≠ k
3.   do x ← x.next
4. return x        ⊳ O(n)：链表不能随机访问
本质权衡：连续 → 换来随机访问；指针 → 换来 $O(1)$ 插入删除。没有免费的午餐。

3 · 栈与队列

栈 Stack —— 后进先出 LIFO

所有操作只发生在栈顶这一端，因此每个操作都是 $O(1)$。

IS-EMPTY(S)
1. if S.top = 0
2.   then return TRUE
3.   else return FALSE

PUSH(S, x)
1. if S.top >= n − 1
2.   then error "overflow"
3. S.top ← S.top + 1
4. S[S.top] ← x

POP(S)
1. if IS-EMPTY(S)
2.   then error "underflow"
3.   else S.top ← S.top − 1
4. return S[S.top + 1]

溢出 overflow：栈满仍 PUSH。  下溢 underflow：空栈仍 POP。

队列 Queue —— 先进先出 FIFO

队尾（tail）入队，队头（head）出队。为了不让指针撞到数组边界，使用循环队列：指针走到末尾就绕回开头。

ENQUEUE(Q, x)
1. Q[Q.tail] ← x
2. if Q.tail == Q.length
3.   then Q.tail ← 1        ⊳ 回绕
4.   else Q.tail ← Q.tail + 1

DEQUEUE(Q)
1. x ← Q[Q.head]
2. if Q.head == Q.length
3.   then Q.head ← 1        ⊳ 回绕
4.   else Q.head ← Q.head + 1
5. return x
判空判满技巧：Q.head = Q.tail 表示空；Q.head = Q.tail + 1 表示满 —— 故意留一个空槽，否则「空」和「满」会撞成同一个状态。

4 · 栈的经典应用

① 括号匹配

规则：每个 (、{、[ 必须与正确的右括号配对。做法：遇左括号入栈；遇右括号则弹出栈顶检查是否匹配。

  • 正确( )(( )){([( )])}
  • 正确((( )(( )){([( )])}
  • 错误)(( )){([( )])}  — 右括号多余
  • 错误({[ ])}  — 括号交叉
  • 错误(  — 左括号未闭合

② 表达式的转换与求值

9 + 3 * 7 + (4 * 5 + 6) * 2  ⟶  9 3 7 * + 4 5 * 6 + 2 * +  ⟶  82

关键区分：同一个栈，在两个算法里装的东西完全不同。
  • 算法一 · 转换（中缀 → 后缀）：栈里装运算符，靠优先级和括号决定何时弹出。
  • 算法二 · 求值（后缀 → 数值）：栈里装操作数（中间结果），规则只有两条。

算法二 · 后缀求值规则

遇到数字就压栈；遇到运算符就弹出两个数、算完把结果压回去。最终栈里剩下的唯一一个数就是答案（本例为 82）。

读入操作操作数栈（底→顶）
9操作数 → 压栈[9]
3操作数 → 压栈[9, 3]
7操作数 → 压栈[9, 3, 7]
*弹出 3、7 → 21 压栈[9, 21]
+弹出 9、21 → 30 压栈[30]
4操作数 → 压栈[30, 4]
5操作数 → 压栈[30, 4, 5]
*弹出 4、5 → 20 压栈[30, 20]
6操作数 → 压栈[30, 20, 6]
+弹出 20、6 → 26 压栈[30, 26]

+弹出 30、52 → 82 压栈[82]

算法一 · 中缀转后缀的规则（栈里装运算符）

  1. 操作数立即输出，运算符压入栈；
  2. 若栈顶运算符优先级高于当前输入运算符，则弹出栈顶并输出；
  3. 遇右括号，不断弹栈输出，直到遇见左括号；
  4. 读到输入结束，把栈弹空、全部输出。
栈把「优先级」和「括号嵌套」这类层级关系，变成了一次线性扫描 —— 这就是数据结构的力量。

补充 · 不转换，直接用两个栈求中缀

其实也可以跳过「转后缀」这一步，用两个栈（操作数栈 + 运算符栈）一边扫描中缀一边求值（Dijkstra 双栈算法）：

  • 遇数字 → 压操作数栈；
  • 遇左括号 → 压运算符栈；
  • 遇右括号 → 不断「弹运算符 + 弹两个操作数 + 计算 + 压回」，直到遇见左括号；
  • 遇运算符 → 先把运算符栈里所有优先级 ≥ 它的运算执行完，再压入当前运算符；
  • 扫描结束 → 把运算符栈弹空，最终操作数栈顶即答案。

三种做法（转后缀再求值 / 双栈直接求值 / 递归下降）本质等价，都依赖栈来暂存「还没轮到处理的东西」。

5 · 插入排序

排序问题

输入：序列 $a_1, a_2, \dots, a_n$。 输出：重排后的 $a'_1, a'_2, \dots, a'_n$，满足 $a'_1 \le a'_2 \le \dots \le a'_n$。

例：8 2 4 9 3 6 → 2 3 4 6 8 9

思路

像打扑克理牌：左手是「已排好序」的一叠牌，每次从右边摸一张新牌（key），从右往左比较、把比它大的牌依次后移，再插到正确位置。

循环不变量（理解本算法的钥匙）：第 i 轮开始时，$A[1\,..\,i-1]$ 是原来那 $i-1$ 个元素、但已按升序排好；$A[i\,..\,n]$ 保持原样、一个都没动。
正确性由三件事保证：初始化（i=2 时左边只有 1 个元素，天然有序）、保持（每轮插完左边仍然有序）、终止（i=n+1 时整个数组有序）。
常见误解：插入排序不做「交换」，而是「腾位置」。做法是：① 先把 $A[i]$ 存进变量 key（必须先存，否则后面的挪动会覆盖掉它）；② 从 $A[i-1]$ 起从右往左扫，凡是比 key 大的都右移一格，腾出的「空位」不断左移；③ 遇到一个 ≤ key 的元素（或走到数组开头）就停，把 key 放进这个空位。 
INSERTION-SORT(A, n)
for i ← 2 to n
  do key ← A[i]
     j ← i − 1
     while j > 0 and A[j] > key
       do A[j+1] ← A[j]
          j ← j − 1
     A[j+1] = key

逐步演示（输入 8 2 4 9 3 6）

轮次key数组状态说明
初始—[8] | 2 4 9 3 6第 1 个元素单独看作已排序
i=22[2 8] | 4 9 3 68 > 2，8 后移，2 插到最前
i=34[2 4 8] | 9 3 68 > 4，8 后移，4 插到 2 后面
i=49[2 4 8 9] | 3 69 > 8，本就在正确位置
i=53[2 3 4 8 9] | 68、4 依次后移，3 插到 2 后面
i=66[2 3 4 6 8 9]8、9 后移，6 插到 4 后面 —— 完成

6 · 算法分析

实验研究 vs 理论分析

实验研究理论分析
做法写程序、跑不同规模的输入、记录时间、画曲线用算法的高层描述，把运行时间写成输入规模 n 的函数
优点直观、真实考虑所有可能输入，与软硬件环境无关
缺点必须先实现；结论不能推广到未测的输入；比较两算法必须同软硬件需要数学抽象

RAM 模型（Random Access Machine）

  • 一台 CPU + 一排内存单元
  • 每个单元可存一个数或字符
  • 内存单元有编号，访问任意单元都花单位时间

运行时间 T(n)

  • 取决于输入（已排好序的序列当然更好排）
  • 用输入规模 $n$ 参数化：$T_A(n) =$ 长度为 $n$ 的输入上算法 $A$ 的耗时
  • 通常求上界 —— 要的是一个性能保证

三类分析

类型定义用不用
最坏情况任何规模为 n 的输入上的最大时间通常用
平均情况所有规模 n 输入上的期望时间，需假设输入统计分布有时用
最好情况某个特定输入上的最快时间永远别用
为什么不用最好情况？因为一个慢算法总能在某些输入上很快 —— 用它等于作弊。

插入排序的复杂度

  • 最坏情况（输入完全逆序）：$T(n) = \sum_{j=2}^{n} \Theta(j) = \Theta(n^2)$（等差数列求和，比较次数恰为 $n(n-1)/2$）
  • 平均情况（所有排列等概率）：同样是 $\Theta(n^2)$
  • 最好情况（输入已经有序）：每轮只比较 1 次就停，共 $n-1$ 次 → $\Theta(n)$
  • 结论：对小 n 尚可，对大 n 完全不行
「适应性」：插入排序是少数最好情况能到 $\Theta(n)$ 的排序算法 —— 数据越接近有序，它越快。这也是为什么很多标准库在小数组上会退化成插入排序（常数因子极小）。

插入排序 vs 归并排序（排序一百万个元素）

插入排序 $\approx n^2/4$
约 70 小时
归并排序 $\approx 2n\lg n$
约 40 秒
机器快 100 倍后
40 分钟 vs <0.5 秒

注意：即使硬件快 100 倍，增长阶的差距依然无法弥补。

7 · 渐进记号

大 O 的定义

$f(n) = O(g(n))$ 当且仅当存在正常数 $c$ 和 $n_0$，使得对所有 $n \ge n_0$ 都有 $f(n) \le c\,g(n)$。

过了 n₀ 之后，c·g(n) 这条线永远压在 f(n) 上面

基本操作

  • 若 $f(n)$ 是 $d$ 次多项式，则 $f(n) = O(n^d)$
  • 步骤：丢掉低阶项、丢掉常数系数
  • 例：$3n^3 + 90n^2 - 5n + 6046 = O(n^3)$
  • 用最小的类：说「$2n$ 是 $O(n)$」而不是「$2n$ 是 $O(n^2)$」
  • 用最简的写法：说「$3n+5$ 是 $O(n)$」而不是「$3n+5$ 是 $O(3n)$」

其他记号

记号类比含义
$f(n) = O(g(n))$$f \le g$渐进上界：存在 $c > 0$、$n_0$，使 $n \ge n_0$ 时 $f(n) \le c\,g(n)$
$f(n) = \Omega(g(n))$$f \ge g$渐进下界：存在 $c > 0$、$n_0$，使 $n \ge n_0$ 时 $f(n) \ge c\,g(n)$
$f(n) = \Theta(g(n))$$f = g$渐进紧界：存在 $c', c'' > 0$、$n_0$，使 $n \ge n_0$ 时 $c'g(n) \le f(n) \le c''g(n)$
$f(n) = o(g(n))$$f < g$严格小于：对任意正常数 $c$，都存在 $n_0$ 使 $n \ge n_0$ 时 $f(n) < c\,g(n)$
$f(n) = \omega(g(n))$$f > g$严格大于：对任意正常数 $c$，都存在 $n_0$ 使 $n \ge n_0$ 时 $c\,g(n) < f(n)$

渐进性能的直觉

$n$ 足够大时，$O(n^2)$ 的算法永远打败 $O(n^3)$ 的算法 —— 这是关心增长阶而非具体常数的原因。但也不要因此忽视渐近更慢的算法：真实工程里常需在常数因子和增长阶之间权衡。

附 · 归并排序 Merge Sort

说明：第一讲只在「插入排序 vs 归并排序」的对比里提到归并排序是 $2n\lg n$，没有展开讲。以下内容按 CLRS 标准补全，便于和插入排序对照理解。

核心思想：分治（Divide and Conquer）

一句话概括：合并两个「已经排好序」的数组只需要 O(n)。所以先把数组拆到不能再拆（每个块只剩 1 个元素，天然有序），再一路合并回来。

步骤做什么
① Divide 分把当前数组从中间劈成两半：$\lceil n/2 \rceil$ 和 $\lfloor n/2 \rfloor$
② Conquer 治对两半递归排序。终止条件（base case）：只剩 1 个元素
③ Combine 合把两个已排序子数组合并成一个有序数组 —— 这一步是全部价值所在

合并（MERGE）的机制

  1. 两个指针 i、j 分别指向两半的第一个元素，比较两者，取小的那个放进结果，对应指针前移；
  2. 某个子数组先空了，就把另一个剩下的直接搬过来。

因为每一步都只前进一格，合并 $n$ 个元素总共只做 $n$ 次操作 → $O(n)$。

伪代码（CLRS 版，用 ∞ 作哨兵）

MERGE(A, p, q, r)              ⊳ 合并 A[p..q] 与 A[q+1..r]
 1. n1 ← q − p + 1 ;  n2 ← r − q
 2. 令 L[1..n1+1] 和 R[1..n2+1] 为新数组
 3. for i ← 1 to n1:  L[i] ← A[p + i − 1]
 4. for j ← 1 to n2:  R[j] ← A[q + j]
 5. L[n1+1] ← ∞ ;  R[n2+1] ← ∞      ⊳ 哨兵，省去越界判断
 6. i ← 1 ;  j ← 1
 7. for k ← p to r
 8.     if L[i] ≤ R[j]
 9.       then A[k] ← L[i] ;  i ← i + 1
10.       else A[k] ← R[j] ;  j ← j + 1

注意第 8 行的 ≤：用「小于等于」而不是「小于」，才能保证稳定性（相等元素保持原有相对顺序）。

Python 实现

def merge(left, right):
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    out.extend(left[i:])       ⊳ 剩下的一股脑搬过来
    out.extend(right[j:])
    return out

def merge_sort(a):
    if len(a) <= 1:            ⊳ base case：天然有序
        return a[:]
    mid = len(a) // 2
    left  = merge_sort(a[:mid])     ⊳ ① Divide ② Conquer
    right = merge_sort(a[mid:])
    return merge(left, right)       ⊳ ③ Combine

复杂度：为什么是 Θ(n log n)

把递归过程画成树，会发现每一层的元素总数都是 n：

  • 第 0 层：1 个子问题，规模 $n$ → 合并工作量 $O(n)$
  • 第 1 层：2 个子问题，各 $n/2$ → 合计 $O(n)$
  • 第 2 层：4 个子问题，各 $n/4$ → 合计 $O(n)$

从 $n$ 二分到 1 一共 $\log_2 n + 1$ 层，所以总时间：

\[ T(n) = O(n) \times (\log_2 n + 1) = \Theta(n\log n) \]

写成递归式：$T(n) = 2T(n/2) + \Theta(n)$，用主定理（Master Theorem）直接得 $\Theta(n\log n)$。

与插入排序对比

插入排序归并排序
最坏时间$\Theta(n^2)$$\Theta(n\log n)$
平均时间$\Theta(n^2)$$\Theta(n\log n)$
最好时间$\Theta(n)$（已有序）$\Theta(n\log n)$
额外空间$O(1)$（原地）$O(n)$（需要辅助数组）
稳定性稳定稳定
对小数组很快（常数因子小）递归开销大
一句话记忆：插入排序是「一个一个安置」，归并排序是「两个有序块一次吃掉」。前者最好情况能到 $\Theta(n)$ 但最坏 $\Theta(n^2)$；后者不管什么输入都稳在 $\Theta(n\log n)$，代价是要多花 $O(n)$ 空间。
