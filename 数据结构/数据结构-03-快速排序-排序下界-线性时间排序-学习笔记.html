1 · 快速排序：分治的另一种写法 p1–p3

讲义开头先把归并排序的分治三步再摆一遍：分（对半切）、递归（各排一半）、合（merge）。 快速排序（quicksort）前两步一样，但把「分」和「合」合并成了一步：

步骤归并排序快速排序
分按位置对半切（$n/2$）按值切成两堆（partition）
递归排两半排两堆
合必须 merge，$\Theta(n)$不需要 —— 切的时候就已经分好了

这是理解快排的第一把钥匙：归并的「分」不花钱但「合」要花钱；快排的「分」花钱（$O(n)$ 的 partition），但「合」免费。 两边都是 $O(n\log n)$，只是把成本挪到了不同的位置。

partition 一次就「钉死」了一个元素的最终位置
Quicksort(A, p, r)
{
    if (p < r)
    {
        q = Partition(A, p, r);      # 分：返回 pivot 的最终位置
        Quicksort(A, p, q-1);        # 递归左堆
        Quicksort(A, q+1, r);        # 递归右堆
    }
}
基例藏在 if (p < r) 里：当区间只剩 0 或 1 个元素时 $p\ge r$，什么也不做 —— 长度 0/1 的数组天然有序。 这是全讲唯一一处「基例不用显式 return」的写法。
为什么不需要 merge：归并排序切的是位置，左半和右半的值域是混着的，所以必须 merge 才能合并有序性； 快排切的是值域，左半的每个元素都 $\le$ 右半的每个元素，所以「左半有序 + 右半有序」直接就是整体有序。 切的方式决定了要不要合。

2 · Partition：全部功夫都在这一个函数 p4–p7

讲义原话：Clearly, all the action takes place in the partition() function。 它要干三件事：原地重排子数组、分成两堆（左 ≤ 右）、返回 pivot 的下标。

写法一：讲义版（双指针，Hoare 思路）

思路是「从两端往中间挤」：左指针找不该在左边的大元素，右指针找不该在右边的小元素，然后交换。

Partition(A, p, r)
    x = A[p];              # 取第一个元素作 pivot
    i = p;
    j = r + 1;
    while (TRUE)
        repeat j--; until A[j] <= x;      # 从右往左找 <= pivot 的
        repeat i++; until A[i] >= x;      # 从左往右找 >= pivot 的
        if (i < j)
            Swap(A, i, j);                # 两个都错位了，交换
        else
            Swap(A, p, j);                # 交叉了：pivot 归位
            return j;
两个指针各自只往一个方向走，所以整个 partition 是 $O(n)$

用 $A=[7,3,8,4,2,9,1]$ 完整走一遍：

写法二：CLRS 版（单指针，Lomuto 思路）

讲义 p7 单独用一页给出了课本的写法 —— 结构更简单，只有一个指针 $j$ 扫描、一个边界 $i$：

PARTITION(A, p, r)
1  x = A[r]                    # 取最后一个元素作 pivot
2  i = p - 1                   # i = 「≤ 区」的右边界
3  for j = p to r - 1
4      if A[j] <= x
5          i = i + 1
6          exchange A[i] with A[j]
7  exchange A[i + 1] with A[r]
8  return i + 1
不变式（CLRS 的精髓）：循环每一轮开始时，区间被分成四段 —— $A[p..i]\le x$、$A[i+1..j-1]\gt x$、$A[j..r-1]$ 未处理、$A[r]=x$。 每次 $A[j]\le x$ 就把「≤ 区」扩一格（第 5–6 行），否则只让 $j$ 前进。 循环结束时把 pivot 换到 $i+1$，正好卡在两段中间。

用 CLRS 的经典例子 $A=[2,8,7,1,3,5,6,4]$，$x=A[8]=4$：

$j$$A[j]$$\le 4$?$i$动作数组
12是1自己换自己2,8,7,1,3,5,6,4
28否1跳过2,8,7,1,3,5,6,4
37否1跳过2,8,7,1,3,5,6,4
41是2换 2↔42,1,7,8,3,5,6,4
53是3换 3↔52,1,3,8,7,5,6,4
65否3跳过2,1,3,8,7,5,6,4
76否3跳过2,1,3,8,7,5,6,4
—换 $A[4]$ 与 $A[8]$—pivot 归位2,1,3,4,7,5,6,8

返回 $q=4$：左边 $[2,1,3]$ 全 $\le 4$，右边 $[7,5,6,8]$ 全 $\gt 4$。

两种写法的区别（考试常问）：
  • pivot 位置：讲义版取第一个，CLRS 版取最后一个。
  • 指针数：讲义版两个指针从两端挤，交换次数少（约 $n/2$ 次）；CLRS 版一个指针扫，交换次数多。
  • 返回值的含义：讲义版 $A[j]$ 是 pivot 本身的位置；CLRS 版 $A[q]$ 也是 pivot 的位置，两半分别是 $A[p..q-1]$ 与 $A[q+1..r]$。
  • 递归写法完全一样 —— 因为两者都满足同一个不变式。

复杂度：两个指针都只单调移动，总共最多扫 $2n$ 步，所以 partition 是 $O(n)$（讲义 p6 直接给了结论）。 注意这是每一层的代价，不是整个算法的代价。

3 · 最坏与最好：差一个 $n$ p8–p10

快排的复杂度完全取决于partition 切得均不均。讲义用三个问题把这件事问透了。

最坏情况：每次切出 1 : n−1

如果每次 partition 都把数组切成「1 个 + 剩下全部」，递归式是

$$T(1)=\Theta(1),\qquad T(n)=T(n-1)+\Theta(n)$$

展开就是 $\Theta(n)+\Theta(n-1)+\cdots+\Theta(1)=\Theta(n^2)$。 递归树是一条斜线，每层只少一个元素，但每层都要付 $O(n)$。

最要命的一点：讲义问 Will any particular input elicit the worst case? 答案是 Yes: already-sorted input。 如果 pivot 取首元素，那么已经排好序的输入（和完全逆序的输入）恰好是最坏情况 —— 每个元素都比后面的都小，pivot 永远是最小值，切出来就是 1 : n−1。
这就是 p11 说的 the real liability of quicksort：最坏情况不是随机的坏运气，而是可预测的、常见的输入。

最好情况：每次正好对半分

$$T(n)=2T(n/2)+\Theta(n)\;\Longrightarrow\;T(n)=\Theta(n\log n)$$

和归并排序的递归式一模一样 —— 这就是第 6 节主定理的情形 2。

哪个更可能？

讲义在这里故意不回答，留到后面两节。直觉上「完美对半」几乎不可能发生，但真正的问题是： 只要切得「不太歪」，就还是 $O(n\log n)$。下一节用 9 : 1 的分割来说明这一点。

情况切分递归式结果
最坏$1 : n-1$（已排序输入）$T(n-1)+\Theta(n)$$\Theta(n^2)$
最好$n/2 : n/2$$2T(n/2)+\Theta(n)$$\Theta(n\log n)$
「很差」$1 : 9$（9 : 1 分割）$T(9n/10)+T(n/10)+\Theta(n)$仍是 $\Theta(n\log n)$（下一节）

4 · 平均情况：先看直觉，再上代换法 p11–p28

第一步：随机化，把「最坏输入」消灭掉

既然最坏情况来自「特定输入 + 固定 pivot」，讲义给了两个解法：

  • 先把输入数组随机打乱，再跑普通快排；
  • 随机选 pivot（randomized-partition）。

两者效果相同：没有任何特定输入能构造出最坏情况了 —— 因为算法本身带了随机性， 对任何输入，坏切分的概率都只和随机选择有关，而不再由输入决定。讲义的原话是 By ensuring that no particular input can be chosen to make quicksort run in $O(n^2)$ time。

第二步：9 : 1 分割的直觉 —— 歪得离谱也还是 $n\log n$

讲义让你「draw it」，即画出 $T(n)=T(9n/10)+T(n/10)+n$ 的递归树：

$\log_{10/9}n=\dfrac{\lg n}{\lg(10/9)}\approx 21.8\lg n$ —— 常数很大，但阶不变

这就是快排「实战很快」的理论依据：即使每次都切成 9 : 1 这种很歪的比例，复杂度仍然是 $O(n\log n)$。 只要分割比例是固定的常数比（$c:(1-c)$，$0\lt c\lt 1$），递归深度就是 $\log_{1/c}n=\Theta(\log n)$，每层代价 $\le n$。

只有一种情况会退化：切分比例随 $n$ 变化（比如每次只切掉常数个元素）， 那时深度变成 $\Theta(n)$，总代价 $\Theta(n^2)$。所以「平均情况好」的关键不是「切得均匀」， 而是「切分比例不依赖 $n$」。

第三步：随机化下的精确平均 —— 递归式怎么来

假设所有元素互不相同，且 pivot 是等概率随机选的。那么 split 有 $n$ 种可能 $(0:n-1),\ (1:n-2),\ \dots,\ (n-1:0)$，每种概率 $1/n$。于是

$$T(n)=\frac{1}{n}\sum_{k=0}^{n-1}\Big[T(k)+T(n-1-k)\Big]+\Theta(n)$$

求和里 $T(k)$ 和 $T(n-1-k)$ 各出现一遍，把下标翻转一下，两者是同一个和，于是合并成

$$T(n)=\frac{2}{n}\sum_{k=0}^{n-1}T(k)+\Theta(n)$$
两个细节： ① 求和到 $n-1$ 而不是 $n$，因为 pivot 自己不属于任何一个子数组（讲义特意强调 which is not included in subarrays）； ② 那个 $\Theta(n)$ 就是这一层 partition 的代价，不是递归项。

第四步：代换法证明 $T(n)=O(n\log n)$

讲义称之为 the dreaded substitution method（让人头疼的代换法），步骤固定三步：

  1. 猜答案：$T(n)=O(n\log n)$；
  2. 写归纳假设：$T(n)\le an\lg n+b$（注意多了个 $b$，用来吸收边界）；
  3. 代入小于 $n$ 的情形，证明对 $n$ 也成立。

代入：

$$T(n)\le\frac{2}{n}\sum_{k=1}^{n-1}\big(ak\lg k+b\big)+\Theta(n) =\frac{2a}{n}\sum_{k=1}^{n-1}k\lg k+\frac{2b}{n}(n-1)+\Theta(n) \le\frac{2a}{n}\sum_{k=1}^{n-1}k\lg k+2b+\Theta(n)$$

剩下的就是把那个求和压住。讲义 p24–p28 用了整整五页来「tightly bound the key summation」，结论是

$$\sum_{k=1}^{n-1}k\lg k\;\le\;\frac{1}{2}n^2\lg n-\frac{1}{8}n^2$$

代回去：

$$T(n)\le\frac{2a}{n}\left(\frac{1}{2}n^2\lg n-\frac{1}{8}n^2\right)+2b+\Theta(n) =an\lg n-\frac{a}{4}n+2b+\Theta(n)$$

只要 $a$ 取得足够大，让 $\dfrac{a}{4}n$ 吃掉 $\Theta(n)$ 那部分，就得到 $T(n)\le an\lg n+b$，归纳成立， 于是 $T(n)=O(n\log n)$。快排平均 $O(n\log n)$。

为什么归纳假设里要加 $b$：因为递归式里有 $\Theta(n)$ 这样的低阶项， 单纯假设 $T(n)\le an\lg n$ 在 $n$ 很小时不成立（$n=1$ 时 $\lg n=0$，右边是 0）。 加一个常数 $b$ 把「小规模 + 低阶项」全兜住，是代换法的标准技巧。

附：关键求和的紧界（讲义 p24–p28）

这一串不等式本身值得看一遍，它示范了「怎么用『每项都不超过最大值』+『配对』来夹住一个和」：

$$\sum_{k=1}^{n-1}k\lg k \;\le\;\frac{(n-1)n}{2}\lg n-\sum_{k=1}^{\lceil n/2\rceil-1}k \;\le\;\frac{1}{2}n(n-1)\lg n-\sum_{k=1}^{n/2-1}k$$ $$\le\;\frac{1}{2}n(n-1)\lg n-\frac{1}{2}\left(\frac{n}{2}\right)\left(\frac{n}{2}-1\right) \;\le\;\frac{1}{2}\left(n^2\lg n-n\lg n\right)-\frac{1}{8}n^2+\frac{n}{4}$$

思路拆解：

  • 把 $\lg k$ 全部放大成 $\lg n$，前 $n-1$ 项的和是 $\frac{(n-1)n}{2}$；
  • 但后一半的 $\lg k$ 其实接近 $\lg n$，前一半差得远，所以要扣掉一部分 —— 扣掉的正好是 $\sum_{k\le n/2}k$，也就是前一半那些「被高估太多」的项；
  • 最后用等差数列求和得到 $-\frac{1}{8}n^2$ 这一项。

结论的量级是 $\frac{1}{2}n^2\lg n-\Theta(n^2)$ —— 首项主导，足够用了。

5 · 换个算法算平均：指示器随机变量 p29–p33

上一节的代换法能证明结论，但要先「猜」对答案，还要处理一个麻烦的求和。 讲义 p29 开始给了第二条路：不写递归式，直接数「一共做了多少次比较」。 这条路的工具是指示器随机变量（indicator random variable），也是概率论在算法分析里最漂亮的一次应用。

把运行时间变成「比较次数」

快排里除了比较之外都是常数时间操作，所以：设 $X$ 为 QUICKSORT 在 $n$ 元数组上做的比较次数，则运行时间是 $O(X)$。 于是问题变成：求 $\mathbb{E}[X]$。

关键观察：每一对元素最多比较一次

这是全节的支点。为什么？因为元素只在被选作 pivot 的那一刻和别的元素比较， 而一旦某个元素成了 pivot，它就退出后续所有递归（不再出现在任何子数组里）。 所以任意两个元素 $z_i,z_j$ 之间，要么比一次，要么一次都不比。

重命名 + 指示器

把数组元素按大小重新命名为 $z_1\lt z_2\lt\cdots\lt z_n$（这是分析技巧，不是真的排序）， 并记 $Z_{ij}=\{z_i,z_{i+1},\dots,z_j\}$ 为「第 $i$ 小到第 $j$ 小」这一段。

定义指示器随机变量

$$X_{ij}=\mathbf{1}\{z_i\ \text{is compared to}\ z_j\}= \begin{cases}1 & z_i,z_j\ \text{比较过}\\ 0 & \text{否则}\end{cases}$$

因为每对最多比一次，总比较次数就是所有指示器之和：

$$X=\sum_{i=1}^{n-1}\sum_{j=i+1}^{n}X_{ij}$$

核心引理：$\Pr\{z_i\ \text{与}\ z_j\ \text{比较}\}=\dfrac{2}{j-i+1}$

为什么？考虑集合 $Z_{ij}$（共 $j-i+1$ 个元素）里谁最先被选为 pivot：

  • 如果最先选中的是 $z_i$ 或 $z_j$ 本身 → 它俩会被比较（另一个此刻还在同一段里，必然和 pivot 比一次）；
  • 如果最先选中的是中间某个 $z_k$（$i\lt k\lt j$）→ 一旦 $z_k$ 成为 pivot， $z_i$ 被分到左边、$z_j$ 被分到右边，从此再也不会同处一个子数组，永远不会比较。

而 $Z_{ij}$ 里每个元素被最先选中的概率相同（随机 pivot），所以

$$\Pr\{z_i\ \text{与}\ z_j\ \text{比较}\}=\frac{2}{j-i+1}$$
这个引理为什么漂亮：它把「两个元素会不会比较」这个全局的、依赖整个递归过程的问题， 压缩成了「一个区间里谁先被选中」这个局部的、只看一个区间的问题。 指示器随机变量的价值就在这里 —— 把复杂事件拆成简单事件的求和。

求和

由期望的线性性（不需要独立性，这是线性性最大的好处）：

$$\mathbb{E}[X]=\mathbb{E}\left[\sum_{i\lt j}X_{ij}\right]=\sum_{i\lt j}\mathbb{E}[X_{ij}]=\sum_{i\lt j}\Pr\{z_i\ \text{与}\ z_j\ \text{比较}\}$$

代入引理，令 $k=j-i$：

$$\mathbb{E}[X]=\sum_{i=1}^{n-1}\sum_{j=i+1}^{n}\frac{2}{j-i+1} =\sum_{i=1}^{n-1}\sum_{k=1}^{n-i}\frac{2}{k+1} \lt\sum_{i=1}^{n-1}\sum_{k=1}^{n}\frac{2}{k} =2(n-1)\sum_{k=1}^{n}\frac{1}{k}$$

而调和级数 $\sum_{k=1}^{n}\frac{1}{k}=H_n=\ln n+O(1)$，所以

$$\mathbb{E}[X]\lt 2(n-1)\big(\ln n+O(1)\big)=O(n\log n)$$
更精确的常数：把求和算紧一点可得 $\mathbb{E}[X]=2nH_n-O(n)\approx 2n\ln n\approx 1.39\,n\lg n$。 这个常数比归并排序的「约 $n\lg n$ 次比较」大一点，但快排的内层循环常数小得多（不需要额外数组、缓存友好）， 所以实战反而更快 —— 这正是讲义 p34–37 反复强调的「渐进相同，常数不同」。
方法思路代价优点
递归式 + 代换法写出 $T(n)=\frac{2}{n}\sum T(k)+\Theta(n)$，猜 $an\lg n+b$，归纳证要猜、要证求和能给出严格的 $O$ 界
指示器随机变量直接数比较次数，用线性性拆开要证一个概率引理不用猜，直觉清晰

6 · 四种排序算法总览 p34–p37

讲义在进入「下界」之前，先把已经学过的四种排序摆在一起对比 —— 这张表是期中期末的高频考点。

算法核心机制最坏平均就地稳定
插入排序 把每个元素插到前面已排序段的正确位置 $\Theta(n^2)$$\Theta(n^2)$是是
归并排序 按位置对半切，递归排序，线性 merge $\Theta(n\log n)$$\Theta(n\log n)$否（需 $O(n)$ 辅助）是
堆排序 建堆 + 反复取堆顶，Heapify 恢复堆序 $\Theta(n\log n)$$\Theta(n\log n)$是否
快速排序 partition 按值切两堆，递归，无需 merge $\Theta(n^2)$$\Theta(n\log n)$是否

讲义对每种算法的评价

  • 插入排序：好写；小输入（$\lesssim 50$ 个元素）快；近乎有序时极快；但最坏 / 平均 / 逆序都是 $O(n^2)$。
  • 归并排序：最坏 $O(n\log n)$，代价是不就地（要额外 $O(n)$ 空间）。
  • 堆排序：最坏 $O(n\log n)$ 且就地，把归并和插入的优点都拿到了。
  • 快速排序：平均 $O(n\log n)$，实战最快；但朴素实现在已排序输入上退化成 $O(n^2)$，必须随机化。
工程上的真实用法：工业级排序（如 C++ std::sort、Java 对象排序）通常是混合的 —— 小数组（$\le 16$ 左右）用插入排序，中段用快排，递归太深时切堆排序防止 $O(n^2)$ 退化（introsort）。 理论上的四种算法，在工程里是按规模分工的。

7 · 比较排序的下界：决策树 p38–p45

到这里，四种排序里有三种都达到了 $O(n\log n)$。自然要问：还能更快吗？ 讲义的回答分两步 —— 先给下界，再「打破」它。

观察：前面所有排序都属于比较排序（comparison sort）—— 它们获取「顺序信息」的唯一手段是两两比较。这个限制就是下界的来源。

决策树：把「比较」抽象成树

任何比较排序算法，对固定的 $n$，都可以画成一棵决策树：

  • 每个内部节点是一次比较，例如「$a_1:a_2$」；
  • 两条出边是两种结果（$\le$ 或 $\gt$）；
  • 每个叶子是一个输出排列。

讲义用插入排序排 3 个元素 $\langle a_1,a_2,a_3\rangle$ 举例，这棵树有 6 个叶子：

决策树把「算法」抽象成了「一条从根到叶的路径」—— 路径长度就是这次执行做的比较次数

下界的三步推导

讲义 p42 用三个设问把证明拆开：

  1. 叶子最少要几个？—— $n$ 个元素有 $n!$ 种排列，每种都必须能被某种输入产生， 所以叶子至少 $n!$ 个。
  2. 高度 $h$ 的二叉树最多几个叶子？—— $2^h$ 个。
  3. 「最少需要的叶子」$\le$「最多可能的叶子」，于是
$$n!\le 2^h$$

取对数：$\lg(n!)\le h$。再用 Stirling 近似 $n!\gt\left(\dfrac{n}{e}\right)^n$：

$$h\ge\lg\left(\frac{n}{e}\right)^{n}=n\lg n-n\lg e=\Omega(n\log n)$$
结论：任何比较排序，最坏情况下至少要做 $\Omega(n\log n)$ 次比较。
推论（讲义 p45）：堆排序和归并排序是渐近最优的比较排序 —— 它们达到了这个下界。
注意这个下界说的是最坏情况（决策树的高度 = 最长路径）。平均情况的下界还要更强一些（约 $\lg(n!)=\Theta(n\log n)$ 同样成立）。
常见的表述错误：「决策树有 $n!$ 个叶子」—— 错，是至少 $n!$ 个。 有些算法（比如带重复元素的比较）可能有更多叶子。下界用的是「至少」，所以 $n!\le 2^h$ 成立。 反过来如果写成 $2^h\le n!$，方向就全错了。

于是问题变成：能不能不靠比较？讲义 p46 的回答是「能，但要看数据长什么样」—— 这就是下面两节的计数排序和基数排序。

8 · 计数排序：不用比较也能排序 p46–p52

下界 $\Omega(n\log n)$ 只约束比较排序。如果换一种「获取顺序信息」的方式 —— 比如直接利用元素的值 —— 就能突破这个下界。

前提条件（不能忽略）

  • 待排序的 $n$ 个数都落在 $[1,k]$ 这个小范围内；
  • 用三个数组：输入 $A[1..n]$、输出 $B[1..n]$、辅助计数 $C[1..k]$；
  • 不做任何元素间的比较。

算法：四步

CountingSort(A, B, k)
1  for i = 1 to k
2      C[i] = 0;                    # ① 清零，O(k)
3  for j = 1 to n
4      C[A[j]] += 1;                # ② 统计每个值出现几次，O(n)
5  for i = 2 to k
6      C[i] = C[i] + C[i-1];        # ③ 前缀和 → 「≤i 的数共有几个」
7  for j = n downto 1
8      B[C[A[j]]] = A[j];           # ④ 从后往前，放到该在的位置
9      C[A[j]] -= 1;
第 ③ 步是灵魂：前缀和之后，$C[i]$ 表示「值 $\le i$ 的元素一共有多少个」。 这正好是值为 $i$ 的元素在输出数组里的「右边界下标」。 所以 $B[C[A[j]]] = A[j]$ 就是「把它放到自己那一组的最后一个空位」。

走一遍：$A=[2,5,3,0,2,3,0,3]$，$k=5$

（这里为了与讲义一致，下标从 0 开始取到 $k=5$。）

阶段$C[0]$$C[1]$$C[2]$$C[3]$$C[4]$$C[5]$含义
② 统计后2023010 出现 2 次，3 出现 3 次……
③ 前缀和后224778$\le 3$ 的有 7 个 → 3 占位置 5,6,7

然后从 $j=8$ 倒着往前扫，每个元素「落到自己组的最后一个空位」：

$A$ 只被读了两遍，$C$ 只被扫了两遍 —— 全程没有比较任何两个元素

为什么是稳定的？为什么必须倒着扫？

第 ④ 步写的是 for j = n downto 1，从后往前。这不是随意的：

  • $C[A[j]]$ 是「值 $\le A[j]$ 的元素个数」，也就是这一组在输出里的最右空位；
  • 从后往前扫，后出现的元素先被放到靠右的位置，于是相同值的元素在 $B$ 里保持了原来的相对顺序 —— 这就是稳定性（stable）。
  • 如果从前往后扫，相同值的元素顺序会反转，算法就不稳定了。
稳定性不是装饰品：下一节的基数排序必须用稳定排序来排每一位，否则整个算法就错了。 计数排序的价值有一半在 $O(n)$，另一半在「它天然稳定」。

复杂度与它的边界

四步分别是 $O(k)$、$O(n)$、$O(k)$、$O(n)$，合计

$$T(n,k)=O(n+k)$$

当 $k=O(n)$ 时就是 $O(n)$ —— 线性时间排序。

「排序不是 $\Omega(n\log n)$ 吗？」不矛盾。 那个下界只对比较排序成立，而计数排序一次比较都没做， 它靠的是「元素值可以直接当下标」这个额外信息。
代价是前提变强了：值域必须是 $[1,k]$ 且 $k$ 不能太大。 用它排 32 位整数就不行了 —— $k=2^{32}\approx 4.29\times10^9$，光清零 $C$ 就要几十亿次操作， 比 $n\log n$ 慢得多。
场景合适吗原因
年龄、成绩、百分制分数合适$k$ 很小且固定
32 位整数不合适$k=2^{32}$，$O(k)$ 直接爆掉
浮点数不合适值域不是有限小整数集
作为基数排序的子程序非常合适每一「位」的值域只有 $k$（如 $2^8$ 或 $2^{16}$）

9 · 基数排序：把大值域拆成小位 p53–p59

计数排序的瓶颈是 $k$ 太大。基数排序（radix sort）的思路是：把一个大数拆成若干「位」，逐位做计数排序， 这样每一位的值域都很小。

讲义的引入很生活化：Sort papers according to student number —— 一叠学生试卷要按学号排序。

关键决策：从最低位开始

直觉上你可能想「先按最高位分堆，再按次高位……」—— 这是错的（或者说，要递归地分很多堆）。 正确的做法是从最低位（least significant digit）开始：

RadixSort(A, d)
    for i = 1 to d
        StableSort(A) on digit i        # 第 i 位（从最低位算起）

走一遍：$329, 457, 657, 839, 436, 720, 355$

趟排序依据结果
初始—329, 457, 657, 839, 436, 720, 355
第 1 趟个位720, 355, 436, 457, 657, 329, 839
第 2 趟十位720, 329, 436, 839, 355, 457, 657
第 3 趟百位329, 355, 436, 457, 657, 720, 839

第一趟按个位排完，顺序看起来「乱七八糟」；但第二趟按十位排完，十位相同的那些元素之间，个位已经是有序的； 第三趟按百位排完，百位相同的那些元素之间，后两位已经是有序的 —— 于是整体有序。

为什么必须从低位开始：因为高位是决定性的。最后一趟按最高位排， 它的结果会覆盖之前所有趟的排序 —— 所以最后一趟必须是「最重要」的那一位。 如果从高位开始，最后按低位排完，高位的顺序就被打乱了，前功尽弃。
换句话说：排序的趟数越靠后，权重越大。低位先排，才能把它的信息「保留」在高位相同的组内部。

正确性证明（归纳）

讲义 p56 给了一个归纳论证，对「趟数」做归纳：

  1. 归纳假设：做完前 $i-1$ 趟后，数组已经按低 $i-1$ 位有序；
  2. 现在按第 $i$ 位做一次稳定排序，证明数组变成按低 $i$ 位有序。

考察任意两个元素 $x,y$，比较它们低 $i$ 位组成的数：

  • 第 $i$ 位不同：排序后 $x,y$ 的相对顺序由第 $i$ 位决定，这正是正确的 —— 低 $i-1$ 位再怎么不同也不影响（因为第 $i$ 位权重更高）。
  • 第 $i$ 位相同：它们的相对顺序应该由低 $i-1$ 位决定，而由归纳假设， 排序前它们已经按低 $i-1$ 位有序了；又因为用的是稳定排序， 第 $i$ 位相同的元素保持原有相对顺序 —— 所以仍然正确。
这就是「必须稳定」的地方：第二种情况完全依赖稳定性。 如果第 $i$ 位的排序不稳定，相同第 $i$ 位的元素会被打乱，低位的排序成果就丢了。

复杂度

每一位用计数排序，值域是 $1..k$，一趟 $O(n+k)$；共 $d$ 趟：

$$T(n)=O(dn+dk)$$

当 $d$ 是常数、$k=O(n)$ 时，$T(n)=O(n)$。

讲义 p58 的例子：排 100 万个 64 位数。 把它看成 4 个「$2^{16}$ 进制」的位（$4\times16=64$），于是 $d=4$、$k=2^{16}=65536$。 基数排序只要 4 趟；而典型的 $O(n\log n)$ 比较排序需要约 $\lg n=20$ 次操作每个元素。 4 趟 vs 20 趟，差距明显。

那为什么还需要别的排序？

讲义最后留了一个开放问题：Can radix sort be used on floating-point numbers? 以及「既然基数排序这么快、这么简单，为什么还用别的？」几点现实考虑：

  • 常数因子：每一趟都要遍历、分配、回写，内存访问模式不如快排的顺序扫描友好；
  • 依赖数据形态：$d$ 和 $k$ 由数据决定，通用库没法预设；
  • 浮点数：不能直接按十进制位拆。理论上可以按 IEEE 754 的位模式排序 （把负数部分取反、正数部分翻转符号位后当成无符号整数），但实现复杂、收益有限， 实际中很少这么做；
  • 比较排序更通用：只要能比较大小就能排，不要求「值可分解成位」。
浮点数的坑（补充）：如果直接按位模式当无符号整数排，负数的顺序会整体反掉 （因为 IEEE 754 用符号-移码表示，负数的位模式越大值越小）。要正确处理，得对负数的位取反。 这是「看起来能用、其实有陷阱」的典型例子。

五个最容易错的地方

  1. 以为快排「平均快」所以「最坏也不差」 —— 已排序输入就是 $O(n^2)$，必须随机化。
  2. pivot 不计入子数组 —— 递归是 $T(q-p)$ 和 $T(r-q)$，求和到 $n-1$ 不是 $n$。
  3. 决策树写成 $2^h\le n!$ —— 方向反了。是「叶子至少 $n!$」→ $n!\le 2^h$。
  4. 计数排序从前往后扫 —— 相同元素顺序反转，失去稳定性，基数排序随之失效。
  5. 基数排序从高位开始 —— 最后一趟必须是最高位，否则前面的排序全被覆盖。
本讲的一句话主线： 快排和归并是「分治」的两种成本分配方式 —— 归并把钱花在合（merge），快排把钱花在分（partition）， 总账都是 $n\log n$。
而「$n\log n$ 到底是不是极限」取决于算法能拿到什么信息： 只能比较 → 决策树给出 $\Omega(n\log n)$ 的硬下界；能直接把值当下标 → 计数排序 $O(n)$ 突破它，代价是前提变强、值域要小； 值域大就拆位 → 基数排序用「多趟稳定排序」把大值域摊平。
复杂度不是算法的属性，而是「算法 + 它能利用的信息」的属性。
