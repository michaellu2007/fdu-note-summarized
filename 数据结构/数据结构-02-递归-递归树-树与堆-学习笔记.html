1 · 递归的三要素 p2–p4

递归（recursion）就一句话：一个方法调用它自己。听起来像循环，但两者的思维方式完全不同 —— 循环是「一步步往前走」，递归是「把大问题交给一个规模更小的同类问题」。

从阶乘看递归的写法

数学定义 $n! = 1\cdot 2\cdot 3\cdots (n-1)\cdot n$ 是连乘，但把它写成递归定义只要两行：

$$f(n)=\begin{cases}1 & \text{if } n=0\\ n\cdot f(n-1) & \text{else}\end{cases}$$

翻成 Python 就是讲义上的三行：

def recursiveFactorial(n):
    if n == 0:
        return 1                      # base case：不再递归
    else:
        return n * recursiveFactorial(n - 1)   # recursive call
递归方法必须有两个部件：
  1. Base case（基例）：输入取这些值时不做任何递归调用，直接返回。至少要有一个。
  2. Recursive call（递归调用）：调用自己，但必须让问题朝基例靠近（这里是 $n\to n-1$）。
讲义原话是两条硬性要求：每一条递归调用链最终必须到达基例；每一次递归调用都必须在朝基例推进。 少了第一条，栈会一直涨到 RecursionError；少了第二条，即使有基例也永远走不到。

递归轨迹（recursion trace）

看递归最有效的方式是把每一次调用画成一个盒子：向下是调用，向上是返回值。以 recursiveFactorial(4) 为例：

向下 4 次 call，向上 4 次 return；乘法全部发生在返回途中
关键直觉：递归的「计算」发生在回程，不是去程。去程只负责把问题拆小、压栈； 真正做乘法的是每一层拿到子结果之后。这也是为什么递归函数总是「先递归到底，再往上算」。

递归 vs 迭代

维度递归迭代（循环）
代码形态函数调用自己，接近数学定义显式循环变量
额外空间$O(\text{递归深度})$ 的调用栈通常 $O(1)$
常数因子大（每次调用有压栈开销）小
适合场景问题本身递归（树、分治、回溯）线性推进、尾递归可改写

阶乘这种「线性递归」改成循环是平凡的，所以它只是教学例子；真正非递归不可的是树和分治 —— 这两类问题的结构本身就是递归的。

2 · 二分查找：递归的第一个实战 p5–p7

问题：在已排序的列表里找 target。线性扫描是 $O(n)$，二分查找把它压到 $O(\log n)$。

三个分支

设当前搜索区间是 data[low..high]，取中点 mid = (low+high)//2，只需比较一次：

  • target == data[mid] → 找到了，返回 mid；
  • target < data[mid] → 目标只可能在左半，递归 (low, mid-1)；
  • target > data[mid] → 目标只可能在右半，递归 (mid+1, high)。

区间为空（low > high）就是基例：返回 False。

def binarySearch(data, target, low, high):
    if low > high:
        return False                       # base case：区间空
    mid = (low + high) // 2
    if target == data[mid]:
        return True
    elif target < data[mid]:
        return binarySearch(data, target, low, mid - 1)    # 左半
    else:
        return binarySearch(data, target, mid + 1, high)   # 右半
每一步都扔掉一半，所以最多 $\lceil \log_2 n\rceil$ 次比较

为什么是 $O(\log n)$

讲义给的论证分两步，注意它的写法比「每次都减半」更严谨：

  • 当前剩余区间长度是 $high-low+1$；
  • 一次比较之后，它变成 $\dfrac{high-low+1}{2}$ 左右（左半或右半）；
  • 于是每次递归都把搜索区间折半，最多 $\log n$ 层。

写成递推就是 $T(n)=T(n/2)+O(1)$，由主定理情形 2 得 $T(n)=\Theta(\log n)$。 每一层只做常数次比较（求中点、比一次），层数 $\log n$，乘起来就是 $O(\log n)$。

前提不能丢：二分查找只对有序数据有效。如果数据没排序，先排序是 $O(n\log n)$， 一次查找反而亏；只有在多次查找同一份静态数据时，排序 + 二分的总账才划算。

3 · 幂运算：同一道题的两种递归 p8–p10

这一节是全讲最重要的方法论示范：同一个问题，递归式写得不一样，复杂度差一个数量级。 两个版本都正确、都是递归、都有基例，但一个 $O(n)$、一个 $O(\log n)$。

版本一：线性递归（$O(n)$）

$p(x,n)=x^n$ 最直白的递归定义：

$$p(x,n)=\begin{cases}1 & \text{if } n=0\\ x\cdot p(x,n-1) & \text{else}\end{cases}$$

它做 $n$ 次递归调用，所以是 $O(n)$。讲义紧接着说：we can do better。

版本二：递归平方（$O(\log n)$）

关键在于不要一次只削掉 1，而是一次削掉一半 —— 用「平方」把指数翻倍的性质反过来用：

$$x^n=\begin{cases}1 & \text{if } n=0\\[2pt] \left(x^{\lfloor n/2\rfloor}\right)^2 & \text{if } n\ \text{is even}\\[2pt] x\cdot\left(x^{\lfloor (n-1)/2\rfloor}\right)^2 & \text{if } n\ \text{is odd}\end{cases}$$

讲义用它算了四个例子，值得逐行看一遍（注意奇偶分支的差别）：

幂展开结果
$2^4$$(2^{4/2})^2=(2^2)^2=4^2$16
$2^5$$2\cdot(2^{4/2})^2=2\cdot(2^2)^2=2\cdot 4^2$32
$2^6$$(2^{6/2})^2=(2^3)^2=8^2$64
$2^7$$2\cdot(2^{6/2})^2=2\cdot(2^3)^2=2\cdot 8^2$128

伪代码（讲义原文，注意奇数分支只算一次 Power 然后乘两次）：

Algorithm Power(x, n):
    Input:  A number x and integer n ≥ 0
    Output: The value x^n
    if n = 0 then
        return 1
    if n is odd then
        y = Power(x, (n - 1) / 2)
        return x · y · y
    else
        y = Power(x, n / 2)
        return y · y
为什么是 $O(\log n)$：参数序列是 $n\to\lfloor n/2\rfloor\to\lfloor n/4\rfloor\to\cdots\to 0$， 长度约 $\lfloor\lg n\rfloor+1$，每层常数次乘法。递推 $T(n)=T(n/2)+\Theta(1)\Rightarrow T(n)=\Theta(\log n)$。
顺带一提：这段代码里的 y = ...; return y·y 不能写成 return Power(...)*Power(...) —— 那会算两遍，退化成指数级（和第 4 节 Fibonacci 犯的是同一个错）。
补充（按 CLRS 补）：这个算法本质就是快速幂 / 二进制幂。 把 $n$ 写成二进制，$x^n$ 就是「按位平方、遇 1 再乘」——递归版和迭代版是同一件事的两种写法。 迭代版把递归栈省掉，常数更小，工程上更常用。

4 · 二分递归：Fibonacci 的指数陷阱 p11–p13

前面两个例子每次只递归一次（线性递归）。Fibonacci 每次递归两次，这是「二分递归」， 复杂度会突然跳档 —— 这一节是整门课关于「递归不能乱写」最直观的教训。

定义与第一版算法

$$F_0=0,\quad F_1=1,\quad F_i=F_{i-1}+F_{i-2}\ \ (i\gt 1)$$ 
Algorithm BinaryFib(k):
    Input:  Nonnegative integer k
    Output: The k-th Fibonacci number F_k
    if k = 1 then
        return k
    else
        return BinaryFib(k - 1) + BinaryFib(k - 2)

数学定义几乎逐字翻过来，正确性毫无问题。问题在代价。

调用次数为什么爆炸

设 $n_k$ 为 BinaryFib(k) 引发的递归调用次数，讲义逐个算了出来：

$k$012345678
$n_k$1135915254167

递推关系是 $n_k=n_{k-1}+n_{k-2}+1$（自己这一层 + 两个子调用）。讲义给了一句很精炼的结论： $n_k$ 大约每两步翻一倍，即 $n_k\gt 2^{k/2}$ —— 指数级。

$k=5$ 就已经 15 次调用；$k=40$ 是十几亿次
根因：递归树里有大量重复子问题。F(3) 在左子树算了一遍，在右子树又算一遍。 朴素的二分递归不做记忆化，所以同一个子问题被反复重算。
解决方向有两条：改写递归式（下面的线性版）、或记忆化 / 动态规划（后面课程会讲）。

第二版：返回一对数，改回线性递归

讲义的思路非常漂亮 —— 让每次递归多返回一个信息，就不需要分叉了：

Algorithm LinearFibonacci(k):
    Input:  Nonnegative integer k
    Output: Pair of Fibonacci numbers (F_k, F_{k-1})
    if k = 1 then
        return (k, 0)                  # (F_1, F_0) = (1, 0)
    else
        (i, j) = LinearFibonacci(k - 1)   # i = F_{k-1}, j = F_{k-2}
        return (i + j, i)                 # (F_k, F_{k-1})

只做 $k-1$ 次递归调用，$O(k)$。核心技巧：递归的返回值不必是答案本身，可以是一个「打包」的中间状态。 多带一个 $F_{k-2}$ 出去，就不用为了它再开一个分支。

版本递归形状递归调用次数复杂度
BinaryFib二分递归（扇出 2）$n_k=n_{k-1}+n_{k-2}+1$，$\gt 2^{k/2}$$O(2^{k/2})$ 指数
LinearFibonacci线性递归（扇出 1）$k-1$$O(k)$ 线性
这一节的通用教训：看到「递归里出现两个自己的调用」，先问一句 —— 这两个子问题真的不相交吗？如果重叠，要么合并信息（本节的招），要么记忆化。 否则一定是指数级。

5 · 归并排序：分治的样板 p14–p30

归并排序（merge sort）是本讲第一个真正的分治算法，也是后面所有复杂度分析的参照物。三步走：

MERGE-SORT A[1 .. n]
1. If n = 1, done.                              # 基例：单个元素天然有序
2. Recursively sort A[1 .. ⌈n/2⌉] and A[⌈n/2⌉+1 .. n].
3. "Merge" the 2 sorted lists.                  # 关键子程序 MERGE

第 1 步是基例，第 2 步是递归（两个子问题，规模各半），第 3 步是合并。 「分」几乎不要钱，全部难度都在「合」。

自底向上：先切成 8 个单元素，再一层层 merge 回去。共 $\lg n$ 层

MERGE：两个有序数组的归并

讲义用了 8 张幻灯片逐帧演示合并过程。它其实是两只手指着两个数组的当前最前端，每次取较小的那个：

步比较输出说明
12 vs 11取右数组首元素
22 vs 92取左数组首元素
37 vs 97
413 vs 99
513 vs 1111
613 vs 1212
713 vs —13右数组空了，剩下整段直接接上
820 vs —20

左数组 $A=[2,7,13,20]$，右数组 $B=[1,9,11,12]$，输出 $1,2,7,9,11,12,13,20$。

为什么 MERGE 是 $\Theta(n)$：每输出一个元素，指针就前进一格，指针只进不退； 一共输出 $n$ 个元素，所以循环体执行 $n$ 次，每次常数时间。比较次数最多 $2n-1$（一个数组先耗尽，另一个直接接上）。 讲义在 p28 明确写了：Time = Θ(n) to merge a total of n elements (linear time)。

递归式：把三步的代价加起来

讲义在 p29 把每行的代价标在右边，直接读出递归式：

MERGE-SORT 的一行代价
1. If n = 1, done$\Theta(1)$
2. 递归排序两半$2T(n/2)$
3. Merge 两个有序表$\Theta(n)$
$$T(n)=\begin{cases}\Theta(1) & \text{if } n=1\\ 2T(n/2)+\Theta(n) & \text{if } n\gt 1\end{cases}$$
讲义的「sloppiness」提醒：严格写应该是 $T(\lceil n/2\rceil)+T(\lfloor n/2\rfloor)$， 因为 $n$ 为奇数时两半不等。但讲义说 it turns out not to matter asymptotically —— 上下取整只差常数，不影响渐进解。做作业时写 $2T(n/2)$ 是可以的，但要知道自己在偷懒。

另外讲义还提到一个实用约定：当 $T(n)=\Theta(1)$ 对足够小的 $n$ 成立时，通常省略基例， 前提是它不影响渐进解。后面写递归式一律只写 $T(n)=2T(n/2)+\Theta(n)$。

结论先行：$T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n)$。 p42 给了实践意义：$\Theta(n\log n)$ 比 $\Theta(n^2)$ 增长慢，所以归并排序在渐近意义上打败插入排序； 实测 $n\gtrsim 30$ 时归并就已经更快（小数组上插入排序常数小，反而赢）。

6 · 递归树：把递归式画开 p31–p53

递归式写出来了，怎么解？讲义先教递归树（recursion tree） —— 它不严格，但能让你一眼看出答案，之后再用代换法补严格性。

例一：$T(n)=2T(n/2)+cn$

把「$2T(n/2)$」画成两个子节点，「$+cn$」写在这个节点旁边（表示这一层自己的代价）：

「每层和相等」是这类树最漂亮的性质，也是 $\Theta(n\log n)$ 的来源

读树的方法，讲义分三步：

  1. 每层的和：第 0 层 $cn$，第 1 层 $cn/2+cn/2=cn$，第 2 层 $cn/4\times4=cn$ …… 每一层都恰好 $cn$。
  2. 树的层数：规模每次除 2，从 $n$ 到 $1$ 要除 $\lg n$ 次，所以高度 $h=\lg n$，共 $\lg n+1$ 层。
  3. 叶子的代价：叶子共 $n$ 个（每个规模 1），每个 $\Theta(1)$，合计 $\Theta(n)$ —— 正好等于最后一层的「$cn$」。
$$T(n)=\underbrace{cn+cn+\cdots+cn}_{\lg n+1\ \text{层}}=\Theta(n\log n)$$

例二：$T(n)=T(n/3)+T(2n/3)+cn$

这棵树不对称：左边缩到 $1/3$，右边只缩到 $2/3$。不对称会带来两个新问题，讲义都用图回答了：

分支比例 $1/3+2/3=1$，所以每层和不会超过 $cn$
两个关键观察（也是这类题的通用套路）：
  1. 每层和 ≤ 根代价：因为子问题规模之和 $\frac{1}{3}n+\frac{2}{3}n=n$，不会「膨胀」。 于是总代价 ≤ $cn\times$（层数）。
  2. 层数看最深的那条路径：一直沿 $2n/3$ 走，$(2/3)^k n=1\Rightarrow k=\log_{3/2}n$。 注意不是 $\log_3 n$，也不是 $\log_2 n$ —— 看最坏的那条分支。
结果 $T(n)=\Theta(n\log n)$。虽然树很歪，但和平衡时的阶一样：$\log_{3/2}n$ 与 $\lg n$ 只差常数倍。
常见错误：把「层数」算成 $\log_3 n$（沿最短路径），得到偏小的上界。 递归树的层数必须取最长路径；叶子数则要数全部叶子，两者不是一回事。

递归树的适用边界

方法优点缺点
递归树直观，能猜出答案；对不等分也有用不是证明，画错一个和就全错
代换法严格（归纳证明）得先知道答案（通常靠递归树猜）
主定理套公式，最快只适用 $aT(n/b)+f(n)$ 形式，且要满足条件

实际解题的标准流程是：递归树猜答案 → 主定理验证（能套则套）→ 套不上再代换法硬证。

7 · 主定理：分治递归式的万能公式 p54–p56

分治算法的递归式几乎都长这样：

$$T(n)=aT(n/b)+f(n)$$

其中 $a$ 是子问题个数，$n/b$ 是每个子问题的规模，$f(n)$ 是「分解 + 合并」这一层自己的代价。 主定理（Master Theorem）直接给出三种情形的答案。

三种情形

情形条件结论谁主导
1 $f(n)=O\!\left(n^{\log_b a-\varepsilon}\right)$，某 $\varepsilon\gt 0$ $T(n)=\Theta\!\left(n^{\log_b a}\right)$ 叶子主导（递归项大）
2 $f(n)=\Theta\!\left(n^{\log_b a}\right)$ $T(n)=\Theta\!\left(n^{\log_b a}\log n\right)$ 两边打平，多乘一个 $\log n$
3 $f(n)=\Omega\!\left(n^{\log_b a+\varepsilon}\right)$ 且 $af(n/b)\le cf(n)$（某 $c\lt 1$，$n$ 充分大） $T(n)=\Theta(f(n))$ 根主导（本层代价大）
怎么记：关键量是叶子总数 $a^{\log_b n}=n^{\log_b a}$。 把「每层代价」$f(n)$ 和「叶子总数」$n^{\log_b a}$ 比大小： 叶子大 → 情形 1（答案就是叶子数）；一样大 → 情形 2（答案再乘 $\log n$，因为有 $\log n$ 层）；$f$ 大 → 情形 3（答案就是 $f$）。
这正是递归树里「哪一层贡献最大」的结论。
同一棵树，三种情况下「最重的一层」位置不同，答案就跟着变

例题：$T(n)=2T(n/2)+100n^{0.9}$

讲义 p56 给的例子值得慢慢做一遍，它专门用来抓「看着像情形 2，其实是情形 1」的错觉：

  1. 读出参数：$a=2$，$b=2$，$f(n)=100n^{0.9}$。
  2. 算临界指数：$\log_b a=\log_2 2=1$。
  3. 比较：$f(n)=100n^{0.9}=O(n^{1-0.1})$，取 $\varepsilon=0.1\gt 0$ —— 满足情形 1。
  4. 结论：$T(n)=\Theta(n^{\log_2 2})=\Theta(n)$。
为什么不能当情形 2：$100n^{0.9}$ 和 $n$ 只差一个常数因子 $100$ 吗？不是。 $n^{0.9}/n=1/n^{0.1}\to 0$，这个差距随 $n$ 增大而无限拉大，不是常数。 主定理的 $\varepsilon$ 要求的正是「多项式意义下更小」，而不是「看起来差不多」。
反过来说，$T(n)=2T(n/2)+100n$ 才是情形 2（$f=\Theta(n^{1})$），答案是 $\Theta(n\log n)$ —— 常数 100 不影响阶。

一句话：主定理不是新知识，它是递归树结论的公式化。 忘了公式时，画三层递归树，看每层和怎么变，答案自己就出来了。

8 · 树：层次结构的抽象 p57–p73

讲义从这里开始进入数据结构部分。树是「层次结构」的抽象模型 —— 组织架构图、文件系统、编程环境里的继承关系，全是树。

基本术语

注意：叶节点（leaf / external）就是「没有孩子的节点」，与「最下面一层」不完全等价
术语定义本例
Root 根没有父节点的节点A
Internal 内部节点至少有一个孩子A, B, C, F
Leaf 叶 / external没有孩子D, E, G, H, I, J, K
Ancestors 祖先父亲、祖父、曾祖父……一直到根I 的祖先：F, B, A
Descendants 后代孩子、孙子、曾孙……B 的后代：E, F, I, J, K
Depth 深度一个节点的祖先个数I 的深度 = 3
Height 高度树中所有节点深度的最大值3
Subtree 子树一个节点连同它全部后代构成的树{C, G, H}
两个容易混的点：
  • 深度 vs 高度：深度是「从上往下数祖先」，高度是「整棵树最深到几层」。单个节点也可以谈高度（它到最远叶子的距离），但讲义这里只定义树高。
  • 叶 ≠ 最底层：本例 D 在深度 1 就是叶子。判断标准只有一个 —— 有没有孩子。

遍历：把一个递归结构线性化

树是非线性的，但输出必须是一维序列。三种经典遍历的差别，只在「访问根」放在递归的哪一步：

遍历顺序一句话典型应用
Preorder 前序根 → 子树们先访问自己，再管孩子打印文档目录、复制一棵树
Postorder 后序子树们 → 根孩子都处理完了才轮到自己算目录总大小、表达式求值
Inorder 中序左 → 根 → 右只对二叉树有意义表达式加括号、二叉搜索树有序输出
 
Algorithm preOrder(v)
    visit(v)
    for each child w of v
        preOrder(w)

Algorithm postOrder(v)
    for each child w of v
        postOrder(w)
    visit(v)

Algorithm inOrder(v)            # 仅二叉树
    if v has a left child
        inOrder(left(v))
    visit(v)
    if v has a right child
        inOrder(right(v))

讲义 p60 用一份「How to Make Money Fast」的文档目录演示前序：访问序号 $1,2,3,4,\dots,9$ 正好是从上到下、从左到右读一遍目录 —— 这就是前序 = 文档大纲的直觉。

p62 用文件系统演示后序：要算 cs16/ 目录的总大小，必须先算完所有子目录， 最后才能把自己那一层的文件加起来。这就是「孩子先于父亲」，非后序不可。

前序的非递归实现

讲义 p61 给了一个用栈改写的版本，思路是「把待访问的节点压栈」：

Algorithm preOrder(v)
    PUSH(S, v)
    while S not empty
        x = POP(S)
        visit(x)
        for each child w of x
            PUSH(w)
顺序陷阱：这样写会把孩子逆序访问（后压的先弹）。 如果要求严格按孩子的自然顺序，必须倒着压栈，或者压栈后再反转。 这是考试和面试里最常被扣分的一行。

二叉树

二叉树是每个内部节点至多两个孩子的树，而且孩子是有序对 —— 左孩子和右孩子不能互换，哪怕只有一个孩子，也要区分它是左还是右。

递归定义（讲义给的第二套定义，更本质）：二叉树要么是空， 要么是一个根，加上有序的一对子树（左、右），且每棵子树本身也是二叉树。

类型条件
Binary tree每个内部节点至多两个孩子
Proper binary tree每个内部节点恰好两个孩子（没有「独生子」）
Complete binary tree所有内部节点都有两个孩子，且所有叶子同深度 —— 完美填满的树
Nearly complete除最后一层外全填满，最后一层的节点尽量靠左（堆用的就是这个）

Proper binary tree 的五条性质

记 $n$ 为节点总数、$e$ 为叶子数、$i$ 为内部节点数、$h$ 为高度。讲义列了六条，但它们其实是 两个方向的结论，理解方向比背公式重要：

性质为什么方向
$e=i+1$每个内部节点恰好两个孩子，边数 $=2i$；树的边数又 $=n-1$，而 $n=i+e$，所以 $2i=i+e-1$恒等式
$n=2e-1$由 $e=i+1$ 与 $n=i+e$ 消去 $i$恒等式
$h\le i$最瘦的 proper 树是一条「链」：每个内部节点带一个叶子，此时 $h=i$上界（最坏）
$h\le (n-1)/2$同上，用 $i=(n-1)/2$ 代入上界
$e\le 2^h$高度 $h$ 的二叉树第 $h$ 层最多 $2^h$ 个节点上界
$h\ge \log_2 e$把上式反过来解下界（最好）
$h\ge \log_2(n+1)-1$把 $e=(n+1)/2$ 代入下界
怎么记这堆不等式：只有两个「锚」—— ① $e=i+1$（proper 的定义直接推出来的）； ② 第 $h$ 层最多 $2^h$ 个节点（二叉树的扇出决定的）。 其余全是这两条 + $n=i+e$ 的代数变形。方向靠「瘦树 / 胖树」两个极端图像判断，不要死背。

完全二叉树的额外性质

性质含义
$n=2^{h+1}-1$每一层都填满，总数是等比级数 $1+2+4+\cdots+2^h$
$e=2^h$叶子全部在最底层，正好 $2^h$ 个
$h=\log_2 e=\log_2(n+1)-1$高度被 $n$ 唯一确定，不再是范围 —— 这是堆能做到 $O(\log n)$ 的根本原因

表达式树：把遍历用起来

算术表达式天然是一棵二叉树：内部节点放运算符，叶节点放操作数。 讲义用 $(2\times(a-1)+(3\times b))$ 举例：

同一棵树，三种遍历得到三种表达式写法

打印表达式 = 中序的特化

Algorithm printExpression(v)
    if v has a left child
        print("(")
        printExpression(left(v))
    print(v.element())
    if v has a right child
        printExpression(right(v))
        print(")")

在标准中序的「左 → 根 → 右」外面，给左子树前补 (、右子树后补 )， 就得到了完全括号化的表达式：((2 × (a − 1)) + (3 × b))。 括号的作用是「不管运算符优先级，强制显式写出结构」。

求值 = 后序的特化

Algorithm evalExpr(v)
    if is_leaf(v)
        return v.element()
    else
        x = evalExpr(left(v))
        y = evalExpr(right(v))
        ⋄ = operator stored at v
        return x ⋄ y

必须后序：算 + 之前，左右两个子表达式的值都得先算好。 讲义 p70 把叶子换成具体数字 $2,5,1,3,2$（即 $a=5,b=2$），问了一句 Reverse Polish? —— 这正是后缀表达式的求值顺序： $$2\ 5\ 1\ -\ \times\ 3\ 2\ \times\ +\;=\;2\times(5-1)+3\times2\;=\;14$$

两种存储表示

链接结构（通用）

每个节点存 element、parent、以及孩子序列（可变长）。 一般树必须这样存，因为孩子个数不定。

二叉树可以简化成三个指针：parent、left、right。

数组表示（限完全二叉树）

把节点按「层序」放进数组，用下标算关系：

  • rank(root) = 1
  • 左孩子：rank = 2·rank(parent)
  • 右孩子：rank = 2·rank(parent) + 1

好处：不用指针，缓存友好；坏处：树不填满就会留空洞，浪费空间。

这一节的主线：树的定义是递归的 → 所以遍历天然是递归的 → 三种遍历的区别只在 visit 的位置 → 不同的 visit 位置对应不同的应用（目录打印、求总大小、表达式加括号 / 求值）。 后面所有树结构（堆、二叉搜索树、平衡树）都是这套框架的特化。

9 · 堆与堆排序 p74–p107

讲义先用一页回顾排序现状，然后引出堆：归并排序最坏 $O(n\log n)$ 但要额外空间； 插入排序就地排序、对小规模或近乎有序的输入很快，但最坏 $O(n^2)$。 堆排序（heapsort）想同时拿到两者的好处：$O(n\log n)$ 且就地。

堆是什么

堆（heap）是满足两个条件的二叉树：

  1. 结构条件：是一棵近完全二叉树（nearly complete）—— 除最后一层外全填满，最后一层尽量靠左。
  2. 堆序条件：$A[\mathrm{Parent}(i)]\ge A[i]$ 对所有 $i\gt 1$ 成立（大顶堆 max-heap）。

第一条保证「能用数组紧凑存储、高度是 $\lfloor\lg n\rfloor$」；第二条保证「最大值一定在根」。 两条合起来才有后面的 $O(\log n)$ 操作。

节点 $i$ 的左孩子是 $2i$、右孩子是 $2i+1$、父亲是 $\lfloor i/2\rfloor$ —— 不需要任何指针

下标公式：不用指针的原因

「近完全二叉树」这个结构条件，让位置关系可以直接算出来：

Parent(i) { return ⌊i/2⌋; }
Left(i)   { return 2*i; }
Right(i)  { return 2*i + 1; }

这就是为什么堆通常用数组实现，而不是链式结构：省掉三个指针，遍历时缓存友好。 代价是「树必须填满」，否则数组里会出现空洞。

1-indexed 还是 0-indexed？讲义（和 CLRS）用 1-indexed， 公式最干净。写成 Python 的 0-indexed 时公式要变：父亲 $\lfloor (i-1)/2\rfloor$、左孩子 $2i+1$、右孩子 $2i+2$。 作业和考试里如果题目没说，按讲义用 1-indexed。

堆的高度

讲义问：$n$ 个元素的堆高度是多少？为什么？

答案 $h=\lfloor\lg n\rfloor$。理由：高度 $h$ 的二叉树至少 $h+1$ 个节点（一条链），最多 $2^{h+1}-1$ 个节点； 而堆是近完全的，它的节点数正好落在 $2^{h}\le n\le 2^{h+1}-1$ 这个区间里 —— 也就是每一层都填满了（除了最后一层），所以 $n$ 与 $h$ 几乎一一对应，解出 $h=\lfloor\lg n\rfloor$。

为什么这件事重要：堆的所有基本操作（Heapify、Insert、ExtractMax）都是「沿一条根到叶的路径走」， 代价正比于高度，因此都是 $O(\log n)$。高度是 $O(\log n)$ 是整个堆结构的地基。

Heapify：让一个节点「沉下去」

这是堆的核心子程序。它的前提很关键，讲义专门列了出来：

  • 给定堆中一个节点 $i$，以及它的左右孩子 $l,r$；
  • 假设以 $l$ 和 $r$ 为根的两棵子树已经是合法的堆；
  • 唯一可能出问题的是 $i$ 自己（比如它刚被换成一个很小的值）。

要做的事只有一件：让 $i$ 的值「往下浮」（float down），直到它不再比孩子小。 具体做法是「和较大的那个孩子交换」，然后对新的位置递归。

Heapify(A, i)
{
    l = Left(i); r = Right(i);
    if (l <= heap_size(A) && A[l] > A[i])
        largest = l;
    else
        largest = i;
    if (r <= heap_size(A) && A[r] > A[largest])
        largest = r;
    if (largest != i)
    {
        Swap(A, i, largest);
        Heapify(A, largest);      # 只递归一条路径
    }
}
为什么只递归一次：交换只影响被换下去的那个孩子所在的那棵子树，另一棵子树没动过、仍然是堆。 所以每层最多一个递归调用 —— 这决定了 Heapify 是 $O(h)$ 而不是指数级。

走一遍：Heapify(A, 2)，$A=[16,4,10,14,7,9,3,2,8,1]$

讲义 p85–p93 用了 9 张幻灯片逐帧演示，过程如下（下标从 1 开始）：

步当前节点它的孩子动作数组
0$i=2$，值 4$l=4$ 值 14，$r=5$ 值 714 最大 → 交换 2↔416,14,10,4,7,9,3,2,8,1
1$i=4$，值 4$l=8$ 值 2，$r=9$ 值 88 最大 → 交换 4↔916,14,10,8,7,9,3,2,4,1
2$i=9$，值 4无（叶子）停止16,14,10,8,7,9,3,2,4,1

只走了 2 层就停了，因为 4 落到了叶子。注意每层都是和「两个孩子里更大的那个」交换 —— 如果和较小的那个换，换完还是比另一个孩子小，得再换一次，就错了。

复杂度：$O(h)=O(\log n)$。讲义 p94 的问法是「Heapify 最多能递归调用自己几次？」—— 答案就是高度，因为每次下沉一层。

BuildHeap：自底向上建堆

有了 Heapify，建堆就很简单：从最后一个内部节点开始，倒着往前，对每个节点调一次 Heapify。

为什么从 $\lfloor n/2\rfloor$ 开始？因为下标 $> \lfloor n/2\rfloor$ 的节点全是叶子 （$2i\gt n$），单个元素的数组本来就是堆，不用处理。

BuildHeap(A)
{
    heap_size(A) = length(A);
    for (i = ⌊length[A]/2⌋ downto 1)
        Heapify(A, i);
}
为什么倒序就对了：处理 $i$ 的时候，$i$ 的两个孩子下标都 $>i$， 已经在这之前处理过了，所以「两棵子树已是堆」这个前提自动成立。这就是 Heapify 能用的条件。 顺序绝对不能反 —— 从前往后处理会破坏前提。

走一遍：$A=\{4,1,3,2,16,9,10,14,8,7\}$

$n=10$，从 $i=5$ 倒着走到 $i=1$：

$i$节点值 / 孩子动作数组
516，唯一孩子 $A[10]=7$7 不比 16 大 → 不动4,1,3,2,16,9,10,14,8,7
42，孩子 14、814 大 → 换 4↔84,1,3,14,16,9,10,2,8,7

为什么 BuildHeap 是 $O(n)$ 而不是 $O(n\log n)$

讲义 p98 先给了一个「显然」的分析：$n/2$ 次调用 × 每次 $O(\lg n)$ = $O(n\lg n)$。 然后连问三句：Is this a correct asymptotic upper bound? Is it asymptotically tight? 答案是：是正确上界，但不紧。真实代价是 $O(n)$。

错在哪？错在「每次都是 $O(\lg n)$」这个假设 —— 那是最坏情况，只有根附近才成立。 绝大多数节点在树底，它们的高度很小，甚至为 0。

讲义的紧分析（p99）：高度为 $h$ 的节点最多有 $\lceil n/2^{h+1}\rceil$ 个，对它调 Heapify 要 $O(h)$，于是

$$T(n)=\sum_{h=0}^{\lfloor\lg n\rfloor}\left\lceil\frac{n}{2^{h+1}}\right\rceil O(h) =O\!\left(n\sum_{h=0}^{\lfloor\lg n\rfloor}\frac{h}{2^{h}}\right)$$

而 $\sum_{h\ge 0}\dfrac{h}{2^h}=2$ 是收敛的常数（这是个标准级数），所以

$$T(n)=O(n\cdot 2)=O(n)$$
直觉版解释：一半的节点是叶子（高度 0，不用干活），$1/4$ 的节点高度 1，$1/8$ 的高度 2…… 干活多的节点极少。「人多的地方活少，活多的地方人少」，加权求和只有常数倍。
对比：如果反过来（每个节点都很高），那就是 $\log n$ 倍了 —— 但近完全二叉树不允许。

Heapsort：把根一个个取出来

既然最大值永远在 $A[1]$，排序就很自然：

  1. $A[1]$ 是最大值 → 和 $A[n]$（末尾）交换，最大值就落到了最终位置；
  2. heap_size--，把末尾排除出堆；
  3. 此时 $A[1]$ 是个小值，调一次 Heapify(A,1) 恢复堆序；
  4. 重复 $n-1$ 次。
Heapsort(A)
{
    BuildHeap(A);
    for (i = length(A) downto 2)
    {
        Swap(A[1], A[i]);
        heap_size(A) -= 1;
        Heapify(A, 1);
    }
}

接着上一节的堆 $16,14,10,8,7,9,3,2,4,1$，看前两轮：

轮交换Heapify 之后已就位
116 ↔ 1（末尾）14,8,10,4,7,9,3,2,116 在最后
214 ↔ 110,8,9,4,7,1,3,214,16 就位

每轮把堆顶（当前最大值）换到已排序区的前端，堆区缩小一格。最后整个数组升序。

为什么是就地（in-place）：所有操作都在原数组里交换，额外空间只有几个下标变量 $O(1)$。 这是堆排序相对归并排序的最大优势。

复杂度

$$T(n)=\underbrace{O(n)}_{\text{BuildHeap}}+(n-1)\cdot\underbrace{O(\lg n)}_{\text{每次 Heapify}}=O(n)+O(n\lg n)=O(n\lg n)$$

讲义 p103 还补了一句实话：Heapsort is a nice algorithm, but in practice Quicksort usually wins —— 堆排序的常数因子和缓存局部性都不如快排，实际很少直接用来排序。 堆真正的价值在优先队列。

优先队列：堆的主战场

优先队列维护一个集合 $S$，每个元素带一个 key，支持三个操作：

操作含义堆上的实现复杂度
Insert(S, x)插入元素 $x$放到数组末尾，然后向上浮$O(\lg n)$
Maximum(S)返回最大 key直接返回 A[1]$O(1)$
ExtractMax(S)删除并返回最大 key取 A[1]，把末尾搬到根，Heapify 下沉$O(\lg n)$
 
HeapInsert(A, key)
{
    heap_size[A] ++;
    i = heap_size[A];
    while (i > 1 AND A[Parent(i)] < key)
    {
        A[i] = A[Parent(i)];      # 父亲下移
        i = Parent(i);
    }
    A[i] = key;                   # 找到位置，落座
}

HeapExtractMax(A)
{
    if (heap_size[A] < 1)
        { underflow error; }
    max = A[1];
    A[1] = A[heap_size[A]];
    heap_size[A] --;
    Heapify(A, 1);
    return max;
}
Insert 与 Heapify 的对称性：Heapify 是「小值往下沉」（修复「父亲太小」）， Insert 是「大值往上浮」（修复「新元素比父亲大」）。 一个是自顶向下、一个是自底向上，两者都只走一条路径，所以都是 $O(\log n)$。

插入 15 到 $[16,14,10,8,7,9,3,2,4,1]$ 的过程：

步位置父亲判断
1$i=11$（新末尾）$A[5]=7$$7\lt 15$ → 7 下移，$i=5$
2$i=5$$A[2]=14$$14\lt 15$ → 14 下移，$i=2$
3$i=2$$A[1]=16$$16\ge 15$ → 停，落座

结果：$16,15,10,8,14,9,3,2,4,1,7$。注意只有「路径上的值」移动，其余元素原地不动。

三种解递归式的方法

方法做法什么时候用
递归树画开，逐层求和，数层数和叶子猜答案、处理不等分（如 $T(n/3)+T(2n/3)$）
主定理比 $f(n)$ 与 $n^{\log_b a}$标准 $aT(n/b)+f(n)$ 形式
代换法猜界 + 归纳证明主定理不适用，或需要严格证明

五个最容易错的地方

  1. 递归不向基例前进 → 栈溢出。写完递归先检查「参数是不是每次都在靠近基例」。
  2. 把 y·y 写成两次递归调用 → 快速幂退化成指数级。Fibonacci 是同一个坑。
  3. 递归树层数取最短路径 → 上界算小。层数必须看最长路径（$T(n/3)+T(2n/3)$ 是 $\log_{3/2}n$）。
  4. 主定理情形 2 误判 → $n^{0.9}$ 与 $n$ 差 $\varepsilon$，属于情形 1，不是「常数倍」。
  5. BuildHeap 顺序写反 → 前提「子树已是堆」不成立。必须从 $\lfloor n/2\rfloor$ 倒序。
本讲的一句话主线： 递归是「把问题变小」的通用手段，但变小的方式决定代价 —— 每次砍一半 → $O(\log n)$；每次砍一个 → $O(n)$；每次分成两个有重叠的子问题 → 指数级。 而递归式（递归树 / 主定理）就是把「变小的方式」翻译成复杂度的工具。 后半讲把递归用到树上（遍历、表达式、堆），本质都是「同样的框架 + 不同的 visit」。
