    算力预算与扩展律

    Compute budgets and scaling · 复旦大学数据科学学院 · Baojian Zhou · 2026-10-21

    这节课回答一个问题：小规模的实验，凭什么能指导一个更大的训练预算？ 前半段把一次训练压缩成四个数字 $(N,D,C,L)$，并算清「六倍」「十六倍」这两个常数从哪来； 后半段把损失写成 $N$ 与 $D$ 的函数，求它在固定算力下的最优分配， 然后——也是最重要的——用一个故意失败的外推例子说明：曲线拟合得很漂亮，不代表它敢预测下一次。

    主线：从一次训练到一条预测
    1. 记账。一次训练 = 一个四元组 $(N,D,C,L)$；算力 $C\approx 6ND$，持久状态 $\approx 16N$ 字节。
    2. 分配。预算固定时，$N$ 和 $D$ 是此消彼长的；损失曲面 $E+A/N^\alpha+B/D^\beta$ 有一个唯一最优解， $N_{\text{opt}}\propto C^{\beta/(\alpha+\beta)}$。
    3. 外推。在几个小预算上拟合幂律，冻结参数，写下对更大预算的预测，然后才揭晓保留的那次运行。

    第三步是本讲的落点：前两步都能算对，第三步仍然可能错得离谱。

    这个「先除一个数再过 softmax」的操作，板书叫 Step 1: rescale logits / Temperature $\tau$：

    $$p_i(\tau)=\frac{\exp(z_i/\tau)}{\sum_j \exp(z_j/\tau)},\qquad \tau>0$$

    • $\tau=1$：原式；板书上单独写了这一行。
    • $\tau\in(0,1)$（板书举例 $0.8,\ 0.9$）：更尖锐，生成更保守；$\tau>1$：更平坦，多样性更高。
    • $\tau\to0^+$ 时退化为 $\arg\max$，也就是 greedy 那一栏。 易错 $\tau=0$ 本身不能代公式（除以零），只能取极限。

    易错 两步的次序不能换

    板书把 Step 1 rescale logits 写在 Step 2 nucleus sample 前面。 先用 $\tau$ 改变概率、再按累计概率截断，与「先截断再调温度」得到的候选集合不是一回事： 前者会让尖锐分布只留很少 token，后者先固定了集合大小。另外，截断后必须重新归一化， 否则抽样分布的质量和不是 1。

    补充 这一步与下一节的 KV Cache 是连着的：无论用哪种解码办法， 模型每一步都只需要当前位置的一个 logits 向量，而为了算它，要把整个前缀再读一遍。 生成 $n$ 个 token 就要读 $n$ 次前缀——这就是缓存的动机。

    0.3 KV Cache：为什么只缓存 K 和 V 板书 推导 补充

    板书只在提纲里写了「① KV cache」四个字，没写原理。补的部分从一个能手算的例子开始。

    先算一遍：第三个 token 到底用了前两个的什么

    只看一层、一个注意力头。记第 $j$ 个位置送进这一层的隐藏向量为 $h_j$，权重为 $W^Q,W^K,W^V,W^O$， 每个位置都做三次投影：

    $$q_j=W^Q h_j,\qquad k_j=W^K h_j,\qquad v_j=W^V h_j$$

    生成到第 $t$ 步时，注意力只用当前位置的 $q_t$ 去问历史：

    $$o_t=\sum_{j=1}^{t} a_{tj}v_j,\qquad a_t=\mathrm{softmax}\left(\frac{q_t[k_1,\ldots,k_t]^{\top}}{\sqrt{d_k}}\right),\qquad y_t=W^O o_t$$

    现在把这部「电影」放到第 4 步：模型要重新算 $k_1$ 吗？不用。 $k_1=W^K h_1$，其中 $W^K$ 是冻结的，$h_1$ 只由第 1 个 token 和因果掩码之前的信息决定 （第 1 个位置看不到第 2、3、4 个位置）；第 4 步新来的 token 不会改变 $h_1$。 所以第 2 步若算出 $k_1=0.5$、$v_1=-0.2$，第 4 步重算还是 $0.5$、$-0.2$—— 重算纯属浪费。$q_1,q_2,q_3$ 则相反：它们各自只在自己那一步被用过，之后再也不会被读，所以不必存。

    一句话原理

    因果掩码让「过去」对「未来」封闭：$k_j,v_j$ 是历史的只读摘要，$q_t$ 是当前步的一次性查询。 于是每层每头维护两份矩阵 $K_{1:t}=[k_1,\ldots,k_t]$、$V_{1:t}=[v_1,\ldots,v_t]$： 输入 prompt 时一次算好（prefill），以后每生成一个 token 只算它自己的 $q_t,k_t,v_t$， 把新的一列追加进缓存（decode）。这就是名字里 K、V 的来历。

    图 0-2　缓存的是「历史摘要」，不是「当前查询」。每一步新增一行，$q_t$ 与缓存里的所有 $k_j$ 打分后即可丢弃。

    省掉了什么，没省掉什么

    每生成 $n$ 个 token无缓存有 KV 缓存机制
    Q/K/V 线性投影次数$\sum_{t=1}^{n}t=\dfrac{n(n+1)}{2}$$n$第 $t$ 步不再重算前 $t-1$ 个位置的投影
    注意力打分（$q\cdot k$）次数$\dfrac{n(n+1)}{2}$$\dfrac{n(n+1)}{2}$当前 $q_t$ 仍要和每个历史 $k_j$ 各打一次分
    数值例：$n=4096$$8\,390\,656$ 次投影$4096$ 次约 $2048.5\times$ 的重复投影被消掉
    随序列增长的显存常量（临时激活）$O(BLn\,h_{\mathrm{kv}}d_{\mathrm{head}})$省的算力换成了常驻显存，见 §0.4
    易错 KV Cache 没有把注意力从 $O(n^2)$ 变成 $O(n)$

    它省掉的是重复计算 K/V 投影（以及相应的激活存储）， 每步 $q_t$ 对 $t$ 个历史位置的打分依然是二次总量。真正被改变的是 decode 阶段的瓶颈： 从「每步重算整个前缀」变成「每步把整块缓存从显存读一遍」，于是推理变得 memory-bandwidth bound。

    维度好处代价 / 条件机制
    计算量前缀的 QKV 投影从 $O(n^2)$ 降到 $O(n)$prefill 阶段仍要并行算完整个 promptprefill 是「一次写入」，decode 才是「每步追加」

    0.4 一笔显存账：KV Cache 有多大 推导 补充

    把上面那张矩阵数一遍元素：$B$ 个序列、$L$ 层、每层序列长 $n$、$h_{\mathrm{kv}}$ 个 KV 头、 每头维度 $d_{\mathrm{head}}$、每个数 $s$ 字节，再乘 2（K 和 V 各一份）：

    $$M_{\mathrm{KV}}=2\cdot B\cdot L\cdot n\cdot h_{\mathrm{kv}}\cdot d_{\mathrm{head}}\cdot s$$

    取一组常见数量级：$L=32$、$h_{\mathrm{kv}}=32$、$d_{\mathrm{head}}=128$、$n=4096$、$B=1$、FP16（$s=2$）：

    $$M_{\mathrm{KV}}=2\times1\times32\times4096\times32\times128\times2 =2\,147\,483\,648\ \text{bytes}=2\ \text{GiB}$$

    配置$h_{\mathrm{kv}}$$M_{\mathrm{KV}}$（$n=4096$）说明
    MHA（每头一份 K/V）322 GiB基线，等于 2048 MiB
    GQA（8 组共享）8512 MiB$h_{\mathrm{kv}}$ 变 1/4，缓存也变 1/4
    MQA（全体共享一份）164 MiB$h_{\mathrm{kv}}$ 变 1/32

    对照一下量级：一个 7B 参数模型用 FP16 存权重约 $7\times10^9\times2=14$ GB。 在 32k 上下文下，单序列的 KV Cache（16 GiB）已经比模型权重还大。 这就是为什么长上下文服务反过来要削弱注意力头数、做分页与量化，而不是只加显卡算力。

    与 §1.5 的 $16N$ 字节不是同一笔账

    §1.5 的 $16N$ 是训练期持久状态（参数、梯度、Adam 的 $m,v$，各 4 字节）， 只随参数量走；KV Cache 是推理期临时状态，随序列长度、batch、层数走。 两者出现在不同阶段，不能相加：7B 训练持久状态约 $16\times7\times10^9=112$ GB（十进制）， 而推理时是 14 GB 权重 + 随 $n$ 变化的缓存。

    易错 算这笔账时最常见的四个漏项
    • 漏掉最前面的 2（K 与 V 两份），结果直接小一半；
    • 把 $d_{\mathrm{head}}$ 写成 hidden size，或反过来用错 $h_{\mathrm{kv}}$（GQA 下它不等于 query 头数）；
    • 漏乘 batch 或 beam 数——beam search 的 $k$ 条候选会各自占一份缓存；
    • 把「训练时 teacher forcing 的激活」当成 KV Cache：训练一次并行看完整个序列，根本没有逐步解码，因此不需要这份缓存。
    开源 核对 · $M_{\mathrm{KV}}$ 的适用条件（transformers / vLLM / rasbt）

    transformers 的 docs/source/en/kv_cache.md 把缓存分成了好几类，正好把 §0.4 的公式补上条件：

    • DynamicCache 默认随生成动态增长；StaticCache 按最大长度预分配， 才能配合 torch.compile 等 JIT 优化——这就是 rasbt 优化版把反复 torch.cat 换成静态张量后 144 → 166 tokens/s 的原因，也说明 §0.4 显存公式里的 $n$ 是已用长度还是预留长度，取决于实现。
    • 要加的限定：§0.4 的线性增长只对全注意力层成立。 滑动窗口 / chunked attention 层（Mistral、Gemma2、Llama4 等）的缓存到窗口大小就停止增长； QuantizedCache（int2 / int4 / fp8）与 offloading 是另两条省显存路径， 但 HF 明确提醒：上下文短、显存够时，量化反而可能伤延迟。
    • prefix caching：把公共 prompt 的 KV 预先填进缓存，多个不同回答复用； encoder–decoder 模型还要额外缓存 cross-attention 的 K/V（本笔记只讲了 decoder-only）。
    • vLLM 的 paged KV cache 设计文档： 按固定 BLOCK_SIZE 分块、块可不连续，decode kernel 是单 query（每序列一步只有一个 $q$）—— 工程上正好印证 §0.3「$q_t$ 一次性、不入缓存」。

    0.5 PEFT 与 LoRA：把「更新」压成两个瘦矩阵 课件 板书 推导

    板书第二行是 Parameter-efficient Fine-Tuning (PEFT)，投影页（P2）标题是 Parameter Efficient Fine Tuning · LoRA，正文三句：

    Transformers have many dense matrix multiply layers — Like $W^Q,W^K,W^V,W^O$ layers in attention.
    Instead of updating these layers during finetuning: Freeze these layers;
    Update a low-rank approximation with fewer parameters.

    先算一遍：一个矩阵要训多少个数

    注意力里一个方阵 $W\in\mathbb{R}^{4096\times4096}$ 有 $4096^2=16\,777\,216$ 个参数。 按 §1.5 的「16 字节每参数」（参数、梯度、Adam 的 $m,v$ 各 4 字节）， 光这一个矩阵的训练状态就是 $16\,777\,216\times16=268\,435\,456$ 字节 = 256 MiB。

    换个做法：不去动 $W$，只学两个瘦矩阵 $A\in\mathbb{R}^{8\times4096}$、$B\in\mathbb{R}^{4096\times8}$，让它们的乘积当作「更新量」。 参数数变成 $8\times4096+4096\times8=65\,536$， 占原来的 $65\,536/16\,777\,216=0.00390625$，即 0.3906%； 训练状态 $65\,536\times16=1\,048\,576$ 字节 = 1 MiB。 从 256 MiB 到 1 MiB，这就是「parameter-efficient」这四个字的全部算术。

    把刚才的做法写成式子（$x\in\mathbb{R}^{d_{\mathrm{in}}}$，$h\in\mathbb{R}^{d_{\mathrm{out}}}$）：

    $$h=Wx+\Delta W x=Wx+\frac{\alpha}{r}\,BAx,\qquad B\in\mathbb{R}^{d_{\mathrm{out}}\times r},\ A\in\mathbb{R}^{r\times d_{\mathrm{in}}},\ \mathrm{rank}(\Delta W)\le r$$

    • $W$ 冻结，只有 $A,B$ 接收梯度；$r\ll\min(d_{\mathrm{in}},d_{\mathrm{out}})$，上面例子里 $r=8$。
    • $\alpha/r$ 是缩放系数：换 $r$ 时保持更新量级大致不变，不必每次重调学习率。
    • 初始化：$B=0$、$A$ 取小随机数，于是训练第 0 步 $\Delta W=0$， 输出与原始预训练模型逐位相同——微调不会一上来就把基座弄坏。
    • 推理时可以把 $W'=W+\frac{\alpha}{r}BA$ 预先合并成一个矩阵， 于是没有额外层、没有额外延迟；只有在需要热切换多个适配器、或同一 batch 混用不同任务时， 才保留两条分支。

    补充 为什么这么少的参数够用？因为「让一个已经会语言的模型改做某类任务」所需的权重改动， 通常集中在很低维的方向上，不需要满秩地重写整个矩阵。 把这件事命名一下：这个维度叫内在秩（intrinsic rank）， 这套方法就是 LoRA（Low-Rank Adaptation），属于 PEFT 家族。 术语放最后说，是因为先看清 16 777 216 → 65 536 这笔账，名字本身没有信息量。

    维度LoRA 的表现机制（不是现象）
    训练显存 / 存储只存 $A,B$ 及其优化器状态；一个基座可配许多几十 MB 的适配器冻结 $W$ 后，参数、梯度、$m,v$ 四份数组都不再为 $W$ 分配
    训练计算省下 $W$ 的权重梯度与优化器更新，不省前向与输入梯度反向仍要把梯度传过 $W$ 回到 $x$；只是 $\partial L/\partial W$ 不必算
    推理延迟合并后零额外开销；不合并时多一次 $BAx$ 的矩阵乘法矩阵加法可预先吸收进权重，但多适配器服务不能吸收
    灾难性遗忘明显缓解$W$ 从未被改动，预训练表示本身不动；代价是表达能力被 $\mathrm{rank}\le r$ 限制
    能力上限适合格式、风格、领域适配；不适合灌入大量新知识低秩增量只能重写少数方向，知识主要还得靠预训练权重或继续预训练
    超参$r$、$\alpha$、以及作用在哪些矩阵（常见只加 $W^Q,W^V$ 或四个都加）$r\uparrow$ 逼近全量微调但参数优势变小；加的矩阵越多，表达能力越强、参数也线性增加
    与量化叠加QLoRA 把基座压到 4 bit，适配器仍用高精度两者作用在不同对象上，可叠加；量化误差不进入 $A,B$ 的梯度
    易错 四个特别容易答错的点
    • LoRA 不减少前向 FLOPs。该走的 $Wx$ 一步没少，还多了 $BAx$；省的是训练状态与权重梯度。
    • $B=0$ 不等于梯度全为零。$\partial L/\partial B=(\partial L/\partial h)(Ax)^{\top}$ 一般非零， 第一步就把 $B$ 推离 0；$\partial L/\partial A$ 此刻为 0，但下一步 $B\neq0$ 后 $A$ 也会动。
    • 忘记 $\alpha/r$。直接换 $r$ 会改变 $\Delta W$ 的量级，等价于悄悄改了学习率。
    • 把「0.39%」当成压缩率或速度比。它是可训练参数之比， 与推理速度、训练总 FLOPs 都不是一回事。

    补充 这一节和 §1.5 的 $16N$ 字节是同一笔账的两个角度： 全量微调要为全部 $N$ 个参数维护训练状态，LoRA 把「需要维护状态的参数」压到极小一部分。 Lecture 08 的板书也点过名——「训练整个 $\theta$ 太贵 → LoRA」； 反过来，本节也解释了为什么后训练阶段常把 LoRA 当成默认选项。

    开源 核对 · LoRA 的公式、初始化与合并（microsoft/LoRA / HF PEFT / self-llm）

    把 原始实现 loralib/layers.py、 PEFT 的 LoRA 文档 和 中文实战笔记 逐行对过，§0.5 的公式与数值都成立，另有四条值得补进来：

    • 源码里 self.scaling = self.lora_alpha / self.r；$A$ 用 kaiming_uniform_、$B$ 用 zeros_。 PEFT 把这个初始化叫 identity transform（恒等变换），即「第 0 步输出与基座逐位相同」； 它还提醒 init_lora_weights=False 只该在调试时用，因为会破坏这条性质。
    • 原始 README 写明： model.eval() 会触发 $W\leftarrow W+BA\cdot\frac{\alpha}{r}$ 的合并，model.train() 再撤销—— 合并本身可逆。但 PEFT 的 merge_and_unload() 不是就地操作、且会丢掉适配器权重； 要可逆得用 merge_adapter()/unmerge_adapter()。这给 §0.5「推理零额外延迟」补了边界。
    • 再算一个缩放：self-llm 的 ChatGLM3 教程用 r=8, lora_alpha=32，缩放 $=32/8=\mathbf{4}$（本笔记复算）。 固定 $\alpha$ 把 $r$ 翻倍，缩放就减半，这正是「换 $r$ 不必重调学习率」的机制。 PEFT 的 rsLoRA 变体把缩放改成 $\alpha/\sqrt{r}$ 以稳住更大的 $r$，此时 $\alpha/r$ 的解释不再适用。
    • 板书把 $W^Q,W^K,W^V,W^O$ 写成四个矩阵，但真实模型常把 QKV 合成一个 nn.Linear： 原始 README 为此提供 MergedLinear，中文教程里 ChatGLM3 写的是 target_modules=["query_key_value"]。 PEFT 默认只作用于 query / value，QLoRA 用 target_modules="all-linear" 覆盖所有线性层。
    • 开源引用结论：原始 README 报告 GLUE 上 LoRA 与全量微调 「comparable or superior」（RoBERTa / DeBERTa 系列），是 §0.5「低秩够用」的经验证据，非本笔记复算。

    0.6.1 五个字母到底指什么（P5、P6）

    板书原文含义与容易含糊的地方
    $L$Loss (PPL)固定评估语料上的平均 token 损失（nats/token）；PPL 是它的指数，见下
    $N$model size (emb.)模型参数量；板书只在 emb. 下划线，按 P8 的 non-embedding 口径理解为不含词表嵌入参数

    $C$training compute (Flops)训练算力，§1.3 给出 $C\approx6ND$
    $L_{\mathrm{val}}$见下式在固定验证文本上的平均负对数似然

    $$L_{\mathrm{val}}=-\frac{1}{M}\sum_{t=1}^{M}\log p_\theta(x_t\mid x_{<t})$$

    板书把 $L$ 标成 PPL（perplexity）是在说两者一一对应：$\mathrm{PPL}=e^{L}$。 手算一遍：$L=3.0\Rightarrow20.0855$，$L=2.5\Rightarrow12.1825$，$L=2.0\Rightarrow7.3891$。 指数关系意味着 loss 降 0.5 不是「好一点」，而是困惑度降到约六成——这也解释了为什么 §1.9 要把 总损失和超出损失分开谈。

    0.6.2 核心结果（P4）：一个曲面，一个约束，两个指数

    Scaling laws (GPT-3) 定律 · Core results
    $L(N,D)=E+A\cdot N^{-\alpha}+B\cdot D^{-\beta},\qquad C\approx kND$
    $N^{*}\propto C^{\frac{\beta}{\alpha+\beta}},\qquad D^{*}\propto C^{\frac{\alpha}{\alpha+\beta}}$
    Given the fixed budget $C$, choose $(N,D)$, so that $L_{\mathrm{val}}$ minimized.

    • $k\approx6$，就是 §1.3 从三次矩阵乘法算出来的那个「六倍」。
    • $E$ 是不可约损失；$A,B,\alpha,\beta>0$，且是指定区间内的经验拟合量，不是物理常数（§1.8 已强调）。
    • 固定 $C$ 时 $N$ 与 $D$ 此消彼长：把参数翻倍，就得把 token 砍一半。求最小值得到板书的两个指数， 完整三步求导在 §2.1，结论是「两项的边际收益相等」：$\alpha AN^{-\alpha}=\beta BD^{-\beta}$。
    自洽性检验：两个指数之和恒为 1

    $\frac{\beta}{\alpha+\beta}+\frac{\alpha}{\alpha+\beta}=1$，所以 $N^{*}D^{*}\propto C^{1}$。 代回约束 $C\approx kND$ 后两边量纲一致——这说明两个指数不是各自独立拟合出来的， 而是同一个约束下的一对。取 $\alpha=\beta=0.5$ 手算：算力翻 4 倍， $N^{*}\propto C^{1/2}$、$D^{*}\propto C^{1/2}$ 各翻 2 倍，$ND$ 正好翻 4 倍， 与 §1.9 的「超出损失乘 $4^{-0.25}=0.7071$」接得上。

    0.6.3 单变量幂律与双对数直线（P7、P9）

    $$L(x)=E+A\,x^{-\alpha},\quad A>0,\ \alpha>0$$

    第一步先把 $E$ 减掉，板书在下面标了 loss gap；第二步只对 gap 取对数：

    • 板书把对数写成带步长的形式（$\log x/\Delta$），换成任何底都只改截距，斜率 $-\alpha$ 不变。
    • $\alpha$ 是区间内的斜率；把直线无限延长到区间外，就是 §2.10 那个故意失败的预测。

    若把 $0.076$ 当成 $\alpha$、$0.095$ 当成 $\beta$，会得到 $\frac{\beta}{\alpha+\beta}=\frac{0.095}{0.171}=0.5556$、$\frac{\alpha}{\alpha+\beta}=0.4444$， 与 §1.10 表里 Kaplan 的经验分配 $0.73/0.27$ 对不上（两组数都独立复算过）。原因不是算错，是混了来源： 这三条幂律是在「另两个因子不瓶颈」的不同实验条件下分别拟合的单变量关系， 并不是在同一个联合曲面 $L(N,D)=E+A/N^\alpha+B/D^\beta$ 上估出的参数； Kaplan 的 0.73 来自算力前沿上的经验拟合（还受 batch、训练步数与早停约定影响）， Chinchilla 才用联合曲面重估出接近 $0.49/0.51$ 的分配。

    另一个坑：这三式都没有不可约项 $E$，形式上 $N\to\infty$ 时 $L\to0$。 它们只是区间内的经验拟合，不能外推到无穷；Lecture 08 §1.1 的勘误说的就是这件事。

    0.6.5 词表随数据变大，所以 tokenizer 必须固定（P6 右侧）

    P6 在变量定义的右边补了一张小图（频率随 rank 下降的直线，即 Zipf 型分布）和两行式子：

    $$|V|\simeq D^{\beta}\qquad\Longrightarrow\qquad \log|V|\approx\beta\log|D|$$

    板书在括号里给了 $\beta$ 的两个数量级：$0.4$ 与 $0.7$。先算一遍这个幂律有多凶： 语料规模 $D$ 翻 1000 倍时，词表大小 $|V|$ 分别乘 $1000^{0.4}=15.8489$、$1000^{0.5}=31.6228$、$1000^{0.7}=125.8925$。 这就是 Herdan–Heaps 型的词表增长：新词按幂律不断出现，词表大小从来不是常数。

    机制上的后果：如果两次训练用了不同的语料规模与不同的分词器， softmax 的归一化项变了、一个「token」代表的信息量也变了，$L_{\mathrm{val}}$ 就不在同一把尺子上。 所以 P4 才专门写 Evaluation text is fixed. Tokenizer, context length.， §2.7 才把「同一分词器、同一评估集、同一上下文长度」列进可比测量的四条契约。 跨分词器实在要比较时，得换成 bits/byte（§附录 B 有换算式）。

    易错 两个 $\beta$ 不是同一个量

    板书 0.6.5 的 $\beta$ 管词表随数据的增长速度（0.4–0.7）， §1.8 曲面里的 $\beta$ 管损失随 token 数下降的速度（玩具值 0.5、Kaplan 0.095）。 同一个希腊字母，两个完全不同的机制，抄公式时别串线。

    1.3 六倍从哪来 课件

    $$\text{前向}\ 2mdh\;+\;\text{输入梯度}\ 2mdh\;+\;\text{权重梯度}\ 2mdh\;=\;6mdh \qquad\Longrightarrow\qquad C\approx 6ND$$

    补充 · 为什么「六倍」这么稳

    反向传播是前向的两倍，这是深度学习里最常用的经验法则，而它在这里有一个干净的解释： 一次反向要算两个东西——传给上一层的梯度（$\partial L/\partial X$）和这一层权重的梯度 （$\partial L/\partial W$）。两者各自是一次与权重同规模的矩阵乘法，所以

    $$\underbrace{1}_{\text{前向}}+\underbrace{2}_{\text{反向}}=3\ \text{次}\times 2mdh=6mdh$$

    而「2」这个因子来自「乘 + 加」。于是三层账都清楚：3 次乘法、每次 2 个运算。

    求和时用了两个近似：$\sum_{\text{稠密层}}dh\approx N$（忽略 bias 与逐元素运算）， $\sum_{\text{所有 token}}m = D$。这两个近似正是后面所有数字的误差来源。

    讲者备注 · 6ND 漏掉了什么
    • token 查表不乘整张嵌入矩阵（只取一行），所以这部分远小于 $6ND$；但绑定词表的输出投影要对整个词表做一次乘法，不算小。
    • 注意力的 $O(T^2)$ 项、激活重计算（checkpointing）、通信都会额外增加 FLOPs。
    • 这是算力模型，不是时间模型：它不告诉你 MFU 是多少，也不告诉你显存够不够。
    • 「$N$ 的口径」必须写清楚：算不算嵌入、MoE 是总参数还是激活参数。

    $$\underbrace{4}_{\theta}+\underbrace{4}_{\nabla\theta}+\underbrace{4}_{m}+\underbrace{4}_{v}=16\ \text{字节/参数}$$

    这就是 Lecture 06 里那张「优化器状态比模型还大」的账在字节层面的写法：

    • $50\times10^{6}\times16=8\times10^{8}$ B $=0.8$ GB（十进制，$10^9$）
    • $200\times10^{6}\times16=3.2\times10^{9}$ B $=3.2$ GB

    1.6 FLOPs 与墙钟时间 课件

    $$t\approx\frac{C}{\text{有效 FLOPs/s}}$$

    对上面那个 $1.2\times10^{18}$ FLOPs 的例子：

    • 假设单卡持续 100 TFLOP/s；
    • 估算计算时间 $\dfrac{1.2\times10^{18}}{10^{14}}=1.2\times10^{4}$ 秒 $\approx$ 3.33 小时；
    • 评估、checkpoint、数据停顿都会再加时间。
    补充 · 「有效」两个字最贵

    $100$ TFLOP/s 是有效吞吐，不是峰值。两者的比值就是 MFU（模型 FLOPs 利用率）。 小模型、短序列、大量通信的并行配置，MFU 都会掉下来——所以更小的模型可能更不划算： 它的 FLOPs 少，但硬件吃不满，实际墙钟时间反而可能不短。

    多卡时用聚合实测吞吐，并且把总 GPU-小时按「所有设备 × 所有尝试次数」计。 另外，FLOP 最优和墙钟最优可以不是同一个选择。

    还有一个记账陷阱：如果吞吐的测量区间已经包含了评估与 checkpoint 的开销， 就不要在时间估算里再把这些开销加一遍——同一份开销只能扣一次。

    1.8 给这个权衡写一个模型 课件

    $$L(N,D)=E+\frac{A}{N^{\alpha}}+\frac{B}{D^{\beta}}$$

    项解释
    $E$该设定下拟合出的损失下界
    $A/N^{\alpha}$模型规模的贡献
    $B/D^{\beta}$训练 token 的贡献

    Hoffmann et al. (2022) §3.3。这是指定区间内的经验拟合模型。

    补充 · 五个数都是「拟合量」，不是物理常数

    玩具曲面里用的无量纲变量是 $n=N/10^{8}$、$d=D/2\times10^{9}$，参数为 $E=1.5$、$A=B=0.8$、$\alpha=\beta=0.5$。把它们带进公式就得到 §1.7 那个式子。

    单位会改变系数。如果把 $N$ 换成「十亿参数」为单位，$A$ 就不再是 0.8—— 所以 $A,B$ 只在声明的单位与区间里有意义，不能跨论文直接比较。

    更要紧的是：这个函数形式假设了「规模」和「数据」两个可分离的幂律项。 重复数据、架构改动、优化器变好、领域切换，任何一条都可能让这个形式失效。 而且拟合出的 $E$ 不能证明它等于语言的真实熵——它只是这个函数形式在这个区间里最好的常数项。

    1.9 怎么读一条幂律 课件

    $$L(C)-E=K\left(\frac{C}{C_0}\right)^{-\gamma}, \qquad \log(L-E)=\log K-\gamma\log\left(\frac{C}{C_0}\right)$$

    • 相同的算力倍数，给出相同的超出损失倍数。
    • 双对数图上的斜率就是 $-\gamma$。
    • 下界 $E$ 未知会让拟合变难。

    本课的参考预算：$C_0=1.2\times10^{18}$ FLOPs。

    补充 · 两个数字是怎么从玩具曲面里出来的

    在最优分配下，两项相等，所以超出损失

    $$L-E=\frac{0.8}{\sqrt{N/10^{8}}}+\frac{0.8}{\sqrt{D/2\times10^{9}}}=2\cdot\frac{0.8}{\sqrt{N/10^{8}}}$$

    而 §2.1 会证明 $N_{\text{opt}}\propto C^{1/2}$，于是 $\sqrt{N}\propto C^{1/4}$， 超出损失 $\propto C^{-1/4}$。所以 $\gamma=0.25$。

    在 $C=C_0$ 处，$N=10^{8}$，上式给出 $L-E=1.6$，于是 $K=1.6$。

    验算一次「四倍算力」：

    $$4^{-0.25}=\frac{1}{\sqrt{2}}\approx0.7071$$

    即超出损失降到原来的 70.7%。但总损失不会降同样的比例—— 因为它还要加上那个不动的 $E=1.5$。这正是「指数好读、绝对量难读」的原因。

    讲者备注 · 直线 ≠ 可以外推
    • 「前沿」有特定含义：在声明协议下，每个算力水平能拿到的最好分配，而不是「任意一次训练」。
    • 在一个有限区间里看到漂亮的直线，完全可能在区间外失效——§2.10 就是这种情形。
    • $E$ 未知时不能直接做 $\log(L-E)$ 的线性回归；研究里通常要联合拟合或做敏感性分析。
    • Kaplan et al. §§1–3 是「幂律」这个经验的动机来源，不是理论保证。

    2.1 固定预算下的最优分配 课件

    把 $D=C/(6N)$ 代进损失模型：

    $$L(N)=E+AN^{-\alpha}+B\left(\frac{6N}{C}\right)^{\beta}$$

    在最小值处：

    $$\alpha AN^{-\alpha}=\beta BD^{-\beta}$$

    $$N_{\mathrm{opt}}\propto C^{\frac{\beta}{\alpha+\beta}}, \qquad D_{\mathrm{opt}}\propto C^{\frac{\alpha}{\alpha+\beta}}$$

    补充 · 三步求导，一个容易踩的坑

    第一步：对 $\log N$ 求导。用 $\log$ 而不是 $N$，是因为所有项都是幂函数，取对数后变成线性，求导更干净。 记 $u=\log N$，则 $\dfrac{d}{du}N^{-\alpha}=-\alpha N^{-\alpha}$，$\dfrac{d}{du}N^{\beta}=+\beta N^{\beta}$：

    $$\frac{dL}{du}=-\alpha AN^{-\alpha}+\beta B\left(\frac{6}{C}\right)^{-\beta}N^{\beta}=0$$

    第二步：两边乘 $N$，第一项回到 $-\alpha AN^{-\alpha}$，第二项变成 $\beta B(6N/C)^{\beta}=\beta BD^{-\beta}$：

    $$\alpha AN^{-\alpha}=\beta BD^{-\beta}$$

    读法：两项的「边际收益」相等。注意只有当 $\alpha=\beta$ 时，才等价于「两项贡献相等」。

    第三步：解出指数。把 $D=C/(6N)$ 代回，整理得

    $$N^{\alpha+\beta}=\frac{\alpha A}{\beta B}\left(\frac{C}{6}\right)^{\beta} \quad\Longrightarrow\quad N_{\mathrm{opt}}\propto C^{\frac{\beta}{\alpha+\beta}}$$

    再用 $D=C/(6N)$ 得 $D_{\mathrm{opt}}\propto C^{1-\frac{\beta}{\alpha+\beta}}=C^{\frac{\alpha}{\alpha+\beta}}$。 两个指数之和恒为 1，这就是 §1.10 那张表里两组指数都加起来等于 1 的原因。

    坑：直接对 $N$（而不是 $\log N$）求导也能做，但会多出 $N^{-1}$ 因子，容易漏项。 另外，只有在系数与指数都为正时，这个驻点才是唯一最小值。

    讲者备注 常数依赖单位与拟合系数。当 $\alpha=\beta$ 时，$N$ 与 $D$ 都按 $\sqrt{C}$ 增长， 比例 $D/N$ 固定。但不要声称真实拟合里一定有 $\alpha=\beta$—— 课件明说了「没有这个主张」。

    补充 · 换分词器之后，nats/token 就不再是同一个单位

    假设分词器 A 把一句话切成 20 个 token，B 切成 18 个。同一个模型的 「每 token 损失」看起来可能变好或变坏，但这不是模型的差别，是分母变了。

    跨分词器比较的常用办法是换成每字节（bits per byte）：

    $$\text{bits/byte}=\frac{L_{\text{nats/token}}\times n_{\text{token}}}{n_{\text{byte}}\times\ln 2}$$

    分母是原始文本的字节数，与分词方式无关，所以可以跨分词器比。

    另外，验证有两个层次，别混：

    • 运行内的留出文本 → 衡量泛化；
    • 跨运行的留出规模 → 检验一条拟合出来的预测。

    后者如果要用作「最终检查」，就必须排除在配方选择与曲线拟合之外。

    它们互相排斥也互相重叠；只凭一个失败的合成点，一个都选不出来。

    还有两条纪律：

    • 先审计测量，再重拟合。如果 $D$ 数错了，重拟合只会把错误固化进系数。
    • 报告残差与敏感性。「$R^2=0.999$」只在拟合区间内成立， 对区间外什么也没说。要把不确定度传播到决策上——比如「该训多大的模型」这个决定对 $\gamma$ 有多敏感。

    最后一句要记住：残差小，不等于找到了最优分配。

    额外的约束什么变了

    推理需求很大训练成本与服务成本都要算
    稀疏专家（MoE）总参数与激活参数不是一回事

    「每参数 20 个 token」是一个与特定训练设定绑定的起始启发式。

    补充 · 20 这个数字的来历与失效条件

    它来自 §1.7 那个曲面：$\alpha=\beta$、$A=B$、且单位取 $N/10^8$ 与 $D/2\times10^9$ 时， 最优点满足 $D/N=2\times10^9/10^8=20$。所以它是这套系数的产物， 被 Chinchilla 的实际拟合「大致」印证，然后被当成经验法则流传。

    它会在三种情况下失效：

    • 数据受限：唯一 token 不够时，重复数据的边际收益会衰减（Muennighoff et al.）， 此时「多给 token」不等于「多给信息」。
    • 推理主导：如果模型要服务几十亿次请求，小模型 + 多训练往往更划算， 因为推理成本按参数量付（Sardana et al.）。这时最优 $D/N$ 会远高于 20。
    • MoE：$N$ 用总参数还是激活参数，会直接改变结论；实际的算子与通信成本也不是一个数字能概括的。

    课件把这页定位成「词汇桥」：知道这些方向存在，但完整的 MoE 优化不在今天的核心范围。

    2.13 更低的损失不等于有用的能力 课件

    留出 NLL 衡量的是平均预测质量。而任务是否成功还取决于：

    • 任务测的是哪些样本、哪些领域；
    • 提示词、解码策略、打分方式的选择；
    • 这个指标能不能区分小模型之间的差别。

    一条损失预测，需要针对预期用途再做一次单独检验。

    讲者备注 · 三种「分数不动」的情形

    平均 NLL 在降，但准确率可能：停在随机水平（任务太难或格式不对）、 已经饱和（任务太简单）、或者分辨率不够（样本太少，噪声盖过差别）。

    代理指标必须针对目标比较被验证过，不能假设它的排序会自动保持到更大规模。 Hoffmann et al. §4.2 报告的是「预训练损失更低、下游评测更好」这类相关性， 不是「某个损失阈值必然带来某种能力」。

    一个可执行的小实验提案

    你有 12 次运行的预算。请指定：一个比较、一个固定评估集、一份运行分配。 其中要包含重复与一个更大规模的验证条件。

    什么样的结果会让你推迟那次大规模运行？

    看答案

    一种可行分配（8 + 4）：

    • 拟合区：2 个候选配方 × 2 个小规模 × 2 个种子 = $8$ 次运行；
    • 验证区：2 个候选配方 × 2 个种子，在更大规模 = $4$ 次运行。

    合计 12 次。注意「12 个槽位」不等于「12 份等量的算力」—— 每一行都要先报价再签字，大规模那 4 次可能吃掉大部分预算。

    推迟的条件（事先声明）：两个配方在拟合区的小规模上差异小于种子间波动， 或者两者的预测区间在目标预算上重叠——这时做大规模运行只是在放大噪声。

    两个拟合规模只是课堂简化，不足以稳健地确定五参数曲面，也不足以估不确定度。 「证据太弱，拒绝宣布赢家」是可接受的答案。

    奥卡姆剃刀与 Scaling Ladder

    任何改进——attention、MoE、优化器、整个架构——都应该过 Scaling Ladder 这一关： 在相同训练 FLOPs 下比性能，或比达到相同性能所需的 FLOPs，再逐级把比较扩展到更大规模； 相对充分调优的 baseline，收益应随规模增大保持下来，而不是越来越小。 文章因此对 nanoGPT / nanochat 一类 speedrun 的夸张宣传保持谨慎：在固定设置上反复调优， 可能只是在过拟合一个 benchmark 与一套训练配置（2026-11-03 补充点名了 Dust 的 speedrun 热潮）。 这与 Sutton 的 The Bitter Lesson、Karpathy 的 Software 2.0 是同一条思路： 能持续从更多计算中获益的通用方法，长期更可能胜出。

    D · 自测十题

    一次矩阵乘法 $m\times d$ 乘 $d\times h$，为什么是 $2mdh$ 而不是 $mdh$？

    答案

    每个输出元素要 $d$ 次乘法和 $d-1$ 次加法；把「乘」和「加」各算一次运算，就是 $2d$，共 $mh$ 个输出。

    $C=6ND$ 里的「6」拆开是哪三件事？

    答案

    前向 $2mdh$ + 输入梯度 $2mdh$ + 权重梯度 $2mdh$。反向是前向的两倍，所以是 $3\times2$。

    50M 参数的模型，FP32 + Adam，持久状态多少？

    答案

    $50\times10^6\times16=0.8$ GB。四个数组：参数、梯度、$m$、$v$。

    两次训练 $6ND$ 相同，能推出什么？不能推出什么？

    答案

    能推出：算力估计相同。不能推出：显存相同（$16N$ 差 4 倍）、损失相同、墙钟时间相同。

    $\alpha=\beta$ 时，$N_{\text{opt}}$ 和 $D_{\text{opt}}$ 各自随 $C$ 怎么长？

    答案

    都按 $C^{1/2}$。因为 $\frac{\beta}{\alpha+\beta}=\frac{1}{2}$。于是 $D/N$ 固定——这就是「每参数 20 token」的来源。

    算力翻四倍，总损失会降到 70.7% 吗？

    答案

    不会。只有超出损失 $L-E$ 降到 70.7%，因为 $E$ 是搬不动的常数项。总损失 $=E+0.707(L_0-E)$。

    为什么 E03 拟合得完美却仍然失败？

    答案

    四个拟合点都在同一个区间、由同一条幂律生成；保留点在区间外，且被人为加了 0.16 的偏移。区间内的完美拟合对区间外没有任何保证。

    一次外推检查失败后，能不能直接用它改曲线？

    答案

    能改，但改完它就变成开发数据，不再是独立检查；要再做一次独立验证，必须另留一个点。

    换分词器之后，怎么比较两个模型的损失？

    答案

    换成 bits/byte（用原始字节数作分母），因为 nats/token 的分母已经变了。

    「每参数 20 token」在什么情况下会明显不适用？

    答案

    数据受限（重复数据收益衰减）、推理需求大（小模型多训练更划算，最优比例远高于 20）、MoE（总参数与激活参数不同）。

    本次补全新增的自测题（8 题；原有「自测十题」完整保留在上）

    KV Cache 为什么只存 K、V，不把 Q 也存起来？

    答案

    因果掩码下 $k_j=W^Kh_j,\ v_j=W^Vh_j$ 只依赖位置 $j$ 之前的输入，后到的 token 不会改变它们， 所以是历史的只读摘要；而 $q_t$ 只在第 $t$ 步被用来和历史打分，用完即弃，旧 $q_{<t}$ 永远不会被再读一次。

    有了 KV Cache，生成 $n$ 个 token 的注意力打分次数变少了吗？$n=4096$ 时呢？

    答案

    没有变：$q_t$ 仍要与 $t$ 个历史 $k_j$ 各打一次分，总量仍是 $\frac{n(n+1)}{2}$。 变少的是 Q/K/V 投影：从 $\frac{n(n+1)}{2}$ 次降到 $n$ 次，$n=4096$ 时是 $8\,390\,656\to4096$，约 $2048.5\times$。 所以缓存没有把注意力的二次项消掉，只是把 decode 变成了带宽瓶颈。

    $L=32,\ h_{\mathrm{kv}}=32,\ d_{\mathrm{head}}=128,\ n=4096$，FP16 单序列，KV Cache 多大？GQA 用 8 个 KV 头呢？

    答案

    $M=2\times1\times32\times4096\times32\times128\times2=2\,147\,483\,648$ B = 2 GiB。 GQA 把 $h_{\mathrm{kv}}$ 变成 8，缓存按同一比例降到 512 MiB；MQA（1 个头）是 64 MiB。 注意最前面的 2 是 K 与 V 两份，且这笔账属于推理期，不能和 §1.5 训练期的 $16N$ 相加。

    一个 $4096\times4096$ 的矩阵用 $r=8$ 的 LoRA，要训多少参数？$B=0$ 初始化会不会让训练卡住？

    答案

    $r(d_{\mathrm{in}}+d_{\mathrm{out}})=8\times8192=65\,536$，是全量 $16\,777\,216$ 的 0.3906%，训练状态 1 MiB（全量 256 MiB）。 不会卡住：$\partial L/\partial B=(\partial L/\partial h)(Ax)^{\top}$ 一般非零，第一步就把 $B$ 推离 0； 只有 $\partial L/\partial A$ 初始为 0，等 $B\neq0$ 后 $A$ 也开始更新。

    双对数图上，$\alpha=\tfrac12$ 与 $\alpha=0.1$ 在 $x:4\to16$ 时各发生什么？为什么必须先减 $E$？

    答案

    gap 乘 $4^{-\alpha}$：$\alpha=\tfrac12$ 时 $0.5\to0.25$（减半）；$\alpha=0.1$ 时 $0.8706\to0.7579$（只降 12.94%）。 必须对 loss gap 取对数才有 $\log(L-E)=\log A-\alpha\log x$ 这条直线，直接画 $\log L$ 不是直线； 而 $E$ 未知时又不能直接对 $\log(L-E)$ 做普通线性回归。

    Kaplan 三张单变量图里的 0.076 / 0.095，能直接当 $L(N,D)$ 曲面的 $\alpha,\beta$ 吗？比较不同 $(N,D)$ 时还要固定什么？

    答案

    不能：三式是「另两个因子不瓶颈」的不同条件下分别拟合的，不是同一联合曲面上估出的参数。 硬代会算出 $0.5556/0.4444$，与 §1.10 表的 $0.73/0.27$ 不一致；而且三式都没有 $E$，不能外推到无穷。 比较时必须固定评估文本、分词器与上下文长度（P4 板书末两行、§2.7 四条契约）， 否则 $L_{\mathrm{val}}$ 的分母与单位都变了——词表还会随 $D$ 按 $|V|\simeq D^{\beta}$ 增长。

    开源实现里，为什么生成两条独立序列之间要 reset_kv_cache()？怎么验证缓存没写错？

    答案

    缓存里存的是上一条序列所有位置的 K/V；不清空，下一轮生成会把它们当成 自己的历史，注意力掩码与 current_pos 也全错位。rasbt 的实现用 reset_kv_cache() 清缓冲区并把位置计数归零；验证办法是让同一模型在有 / 无缓存两种模式下生成， 逐 token 比对文本必须完全相同——索引错误很容易让两者发散。

    LoraConfig(r=8, lora_alpha=32) 的缩放是多少？为什么板书上的 $W^Q,W^K,W^V$ 在真实模型里可能只对应一个模块名？

    答案

    缩放 $=\alpha/r=32/8=4$。固定 $\alpha$ 把 $r$ 翻倍，缩放减半，这就是换 $r$ 不必重调学习率的机制 （rsLoRA 例外，它用 $\alpha/\sqrt r$）。板书为讲解把 Q/K/V 画成三个矩阵，但实现常把三者合并成一个 nn.Linear：ChatGLM3 的教程写 target_modules=["query_key_value"]， microsoft/LoRA 也为此提供 MergedLinear。所以 target_modules 要按具体模型的模块名写， 不能照抄板书符号。
